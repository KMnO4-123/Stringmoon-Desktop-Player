# Stringmoon · 桌面音乐播放器

Electron 44 + TypeScript + React。协议侧见 `CONTRACT.md` §3（冻结，逐字实现）。
界面以 Nothing 三通道状态编码为基础，加入液态玻璃控件、音乐空间、沉浸播放和响应式音效工作台。

## 曲库目录与封面

- **曲库目录是一组，不是一个**：用户加进来的目录都记在 `userData/library.json`，
  下次启动按顺序全部扫描 —— **这次看到的曲库，下次启动原样复现**。
  曲库视图顶部有「N 个曲库目录」面板，可以看每个目录、标记不可用的、并逐个移除
  （移除只影响曲库，**不删磁盘上的文件**）。从未管理过目录时回退到内置默认目录，
  它在用户第一次增删时被固化进列表（否则会话内是「默认+新目录」、重启后只剩新目录）。
  某个目录不见了（拔盘/删目录）时只提示哪几个不可用，继续扫可用的那些 ——
  一个盘没插不该让整个曲库消失。
- **移除目录不需要重新扫盘**：引擎 catalog 仍留着那些条目（它没有清空命令，见 CR-013），
  但可见集只认当前目录，所以曲目立刻消失、重新加回来也立刻恢复。
- **曲目身份按归一后的 path 判定**（`src/shared/library.ts` 的 `libraryPathKey`）。
  引擎把 `scan` 收到的目录字符串原样拼进每首曲目的 path，所以同一个目录换个写法
  （正斜杠 ↔ 反斜杠）会被它当成另一批新曲目，91 首变 182 首（实测，见 CR-013）。
  应用侧按归一 path 去重，并且同一会话内不重扫已扫过的目录（重扫没有正确结果：只增不换）；
  想拾取磁盘新增文件就重启应用。
- **正在播放从引擎全量列表解析，曲库列表只显示所选目录**：移除正在播放那首歌所属的目录时，
  歌继续放、播放栏继续报它自己的名字，而曲库列表里它已经不在 —— 两者都不说谎。
- **自定义封面可撤销**：悬停封面时，只有当前显示的是「用户自己选的图」才出现
  「移除封面」；它只删 `artwork.json` 里的映射，**不删用户的图片文件、不改音乐文件**，
  移除后回到自动读取（嵌入图 → 同名图 → cover/folder/front → 字形封面）。

## 换真引擎

`EngineHost`（`src/main/engine-host.ts`）解析顺序：环境变量 `TWILIGHT_ENGINE`（+可选
`TWILIGHT_ENGINE_ARGS`）优先；未设置时默认探测 `..\..\engine\bin\twilight-engine.exe`，
再退回 `tools/mock-engine.mjs`（node 子进程模式）。

```
# 显式指定（等价于默认探测）：
TWILIGHT_ENGINE=<仓库根>\engine\bin\twilight-engine.exe pnpm dev
```

协议纪律（BRIEF §3 / CONTRACT §3 铁律的落地）：
- stdout 逐行 `JSON.parse`，**任何一行解析失败 = 引擎 bug**，红色横幅 + 主进程日志，绝不静默跳过；
- 命令带自增 `id`，回复按 id 关联，超时显式失败；意外断连自动重启（≤3 次）；
- `state`/`position` 及 `get_state` 回复是权威值，UI 不自行外插时间；高频进度使用独立仓。
- `hello` 保存能力声明，`state.dspActive`/`dspModules` 驱动 C2；`get_state` 仅用于启动/重连同步，无定时轮询。
- `window.twilight.request` 返回应用内部结果 envelope；渲染层 `engineRequest` 解包数据或重建带 `code/kind` 的错误。此 envelope 不改变引擎 JSON Lines 协议。

## 首页监测带与高度预算

首页底部是一条**监测带**：左列「EQ 频响」、右列「频谱」，两者**底边对齐**（各列最后一个元素，列内多余留白
落到图的上方而不是下方），读起来是并排的一对，而不是一高一低谁也没对齐。

高度不是拍出来的，是两条**既有布局质量线**倒推出来的：

| 约束 | 来源 | 结果 |
|---|---|---|
| 歌词列 ≥ 160px（1280） | `test-player-ui` 的布局断言 | 舞台 540px、频谱绘图区 88px 后，歌词 **185.3px** |
| 歌词列 ≥ 120px 且 EQ 图不被播放栏遮住（900×600） | 同上 | 频谱收成读数条（绘图区 `display:none`），歌词 **134.4px** |

改动这三个数字前先跑 `.smoke/probe-layout.mjs`（不需要声卡，直接量两种尺寸下的几何）。

**播放栏高度**是令牌 `--playbar-height`（76px），外壳网格行与 `.playbar` 共用它 —— 各写一个数迟早错位。
压缩后信号弹层仍完整浮在播放栏之上（`.signal-popover` 的 `bottom` 不用改）。

**横向配比只由 `player.css` 定义**（`theme.css` 里那份同属性规则曾把它整个盖掉，是死代码，已删）：
`0.87fr / 1.6fr / 1.14fr` —— 左块只要缩略图与曲名，右块要塞信号/音量/沉浸三个控件。
均分（原 `1fr / 1.6fr / 1fr`）会让音量滑条只剩 66px，0–100% 挤在 66px 里没法精调；现在约 **98px**。
音量读数带单位（`42%`），静音时它仍显示用户选的档位。

## 实时频谱（CR-015）

首页右列底部、**EQ 频响图右侧**（也就是歌词下面那块区域）有一条**实时频谱**：与 EQ 图**同一套画布语法** ——
同一根对数频轴、同样的 dB 纵轴、同样的线 + 面，只是数据来自引擎的 `ev:'meter'`（CR-015，owner 已接受）。

它同时是「电平监测」：读数行给响度（400 ms Momentary LUFS）、峰值、真峰值、增益衰减（`gainReductionDb`，
在**限幅之前**采样，所以能看出限幅前是否过载）。

四条纪律：

1. **30 Hz 不进 React 渲染** —— 曲线与读数都用 ref 直接改 DOM，React 只在「有没有数据」和宽度变化时重渲染
   （否则每秒 30 次整树 diff，正是 `position` 那一课）。数据走独立的 `meterStore`，与 `positionStore` 同构。
2. **没有数据就不画曲线** —— 画一条平线等于宣称「此刻静音」，而我们并不知道。面板如实显示「等待引擎推送」。
3. **纵轴固定不自动缩放**（-72…0 dB）：会自己跳的纵轴没法当监测看。
4. **换曲即清空**：上一首的曲线继续挂着就是谎称它属于这一首。断连同样清空。

mono 源时数组长度为 1，**不复制成两条**（复制会看起来像「两个声道都正常」）。
真峰值基准是「样本峰值」时（libebur128 在 ≥192 kHz 不建插值器，真峰值退化为样本峰值）必须看得见标注 ——
不能把样本峰值标成真峰值。监测**不改样本**，所以它不进 `dspModules`、不影响 `outputPerfect`，C2 路径也不多一段。

## 播放栏控件

播放栏有六条传输命令（上一首/播放/停止/下一首，另有静音与音量）、进度条与三个扩展控件。
三个扩展控件的共同纪律：**引擎的 state 事件是权威值，界面只跟随、不自己记**。

| 控件 | 命令 | 为什么这样 |
|---|---|---|
| 循环模式（顺序/列表/单曲/随机） | `set_repeat` | 引擎侧是**一个四态枚举**（`player.hpp:36`），随机取代循环而不是叠加 —— 所以界面也是一个按钮循环四态，不是「循环+随机」两个开关。当前模式回读自 `state.repeatMode` |
| 静音 | `set_muted` | 静音**不改变音量**（`app.cpp:513` 的回复注释专门纠正把二者等同的客户端）。所以静音时音量条停在用户选的档位、只把「正在静音」显示出来；拖动音量会**显式**发一条取消静音，而不是隐含副作用 |
| 输出模式偏好（自动/独占/共享） | `set_output` | 弹层里同时给出**请求**与**实际**：请求独占而被端点拒绝时会降级成共享，此时偏好仍是独占、实际是共享并附原因。只显示其中一个就等于替引擎宣称一件没发生的事（CONTRACT §3.4） |

三个离散控件都做**乐观设置 + 失败回滚**：命令失败时退回原值并报协议错误 —— 一个静默失败的开关就是一句假话。
旧引擎（2026-10-15 20:35 之前的构建）不发 `repeatMode`/`muted`，此时**保持当前值**而不是回默认，
否则用户刚设的模式会在下一个 state 事件上被抹掉。

## 日志脱敏（MASTER-B-app §A1）

`src/shared/redact.ts`，黑名单式遮蔽，**接到全部日志出口**：引擎 stderr（`engine-host.ts`，今天最大的泄漏面）、
四处协议异常打印、`main/index.ts` 的协议行解析失败、渲染层 `[engine:log]`。

遮什么：网易云与 QQ 的会话 cookie 名（`MUSIC_U`/`__csrf`/`MUSIC_A`/`NMTID`/`qm_keyst`/`skey`/`uin`…）、
`Authorization`/`X-Api-Key`/`Cookie`/`Set-Cookie` 头、URL 里的 `token`/`sign`/`access_token` 等参数、`Bearer` 前缀。

两条刻意的取舍：**黑名单式，不做"智能识别"**（漏遮一次的代价远大于多遮几个字符）；**宁可过度遮蔽**
（因此普通参数 `key=` 也会被遮 —— 日志的用途是排障，不是留档原文）。

测试断言的是「**原文里的秘密子串不得出现在输出里**」，而不是比对固定的遮蔽结果：前者不管遮成什么形式都成立，
测的是"有没有泄漏"这个真问题。还有一条反向对照：没有凭据的日志行必须**逐字节原样通过**。

## 长列表：虚拟化（MASTER-B-app §A4-1）

曲库列表**只渲染可见窗口**（约 10 行 + 上下各 4 行 overscan），高度由「总行数 × 行高」撑开，窗口用 `transform` 平移。

| 2000 首 | 之前（content-visibility） | 现在（虚拟化） |
|---|---|---|
| DOM 节点 | 30,183 | **370**（目标 < 2,000 ✓） |
| 渲染行 | 2,000 | 12 |
| 渲染进程工作集 | 331MB | **214MB** |
| 切到曲库 | 936ms | **246ms → 14ms**（见下） |

**池化的关键是 key 用槽位而不是曲目 id**：窗口滑动时 React 复用同一批 DOM 实例、只换内容与数据属性。
无障碍按 ARIA 的 windowing 约定：listbox 标 `aria-rowcount`（总数）、每行标 `aria-rowindex` 与 `data-row-index` ——
屏幕阅读器据此知道「总共 N 项、当前第几项」，而不是以为列表只有十来项。
键盘导航跨越窗口边界时先滚动、再聚焦（目标行此刻可能还不在 DOM 里）。

行高**读 CSS token `--row-height`**（不另写常量）：它同时是 `min-height`、`content-visibility` 的占位估计、
以及虚拟化的固定行高 —— 三处一个值，CSS 改了 JS 会跟着变。

### 视图切换的 246ms 与 14ms

切页慢的那部分**与曲库规模无关**（91 首 670ms ≈ 2000 首 673ms）。实测定位：

1. `AnimatePresence mode="wait"` 要等旧视图**判完成**才挂载新视图；退出动画 306ms 视觉到位，却到 **554ms** 才判完成 ——
   拖后腿的是整屏 `filter: blur()`（MASTER-B-app **红线 6**：大面积模糊不要逐帧），且主线程 `longtask` 为 **空**、与减少动态效果无关。
2. 去掉整屏 blur、换成快速弹簧（`snap`，response 0.12s）后，串行模式切页 632 → **246ms**。
3. 最终采用**交叠式**（不再 `mode="wait"`）：新视图 **9ms 进入 DOM、14ms 画出首行**，交叉淡入约 200ms 后旧视图移除。
   既满足「切页 < 200ms」，也让点击后立刻有反馈（串行模式有 246ms 的「什么都不动」）。

## 长列表（规模）旧记（content-visibility）

曲库行不用虚拟列表，但每行都开了 `content-visibility: auto` + `contain-intrinsic-size: auto var(--row-height)`：
屏幕外的行不参与布局/绘制/样式计算，DOM 仍在，滚动、聚焦与无障碍语义不变。占位高度与 `min-height`
共用同一个令牌（`--row-height`）——估错高度会让滚动条抖动。

行的入场动画是 **CSS** 而不是每行一个 Motion 实例。实测 2000 首（同一套压测脚本）：

| | 优化前 | 优化后 |
|---|---|---|
| 切到曲库渲染 | 1224 ms | **936 ms** |
| 渲染进程工作集 | 509 MB | **331 MB** |
| DOM 节点 | 30,183 | 30,183（未变，虚拟列表才改这个） |

减少动态效果不需要在组件里判断：全局 `@media (prefers-reduced-motion: reduce)` 已经关掉了动画。

## 三通道状态（DESIGN v5）

C1 表达播放与严重级别；C2 用节点、折线、波浪和虚线表达信号路径，title/aria 提供完整状态。
只有引擎报告 `degradeReason` 才画降级虚线；共享模式本身不被推断为错误。
DSP 能力与生效状态分别消费；xrun 数字取 state 的会话累计值，事件只触发有限次数闪光。
颜色、字号、时长与曲线来自 `tokens.css`，基线已收紧至零。

## 平台接入（流媒体源）

按 CONTRACT §4 的 **Folia 方式**：**用户自备 API 服务端，应用负责拉起**。
主进程动态分配端口、探活、崩溃退避重启、退出清理；渲染层只看到 `127.0.0.1:<port>`。

| 源 | 服务端 | 端口变量 | 说明 |
|---|---|---|---|
| 网易云 | `@neteasecloudmusicapienhanced/api` | `PORT` | 扫码登录；`yv=-1` 才有字级 yrc |
| QQ 音乐 | `@yakult-green-tea/qq-music-api` | `PORT` | 扫码登录；不登录搜歌常被上游拒绝 |
| 通用源（酷狗/酷我/百度/QQ/网易云） | `meting-api` | `HTTP_PORT` | 无登录态；取直链需要 HMAC 令牌 |

播放链路：`取直链 → LoopbackMediaProxy（带 Referer/UA）→ 引擎 open { url }`，
直链**不经过渲染层**，一个 token 只服务一次播放。

界面：左栏有**来源区**（本地 / 网易云 / QQ / 通用源，带真实状态与登录、启动、停止）与**歌单来源页签**；
**歌曲中心**一个视图里搜本地或平台、切换来源、直接播放、打开平台歌单；
曲库与歌单都支持多选批量操作（全选 / 反选 / 加入队列 / 下一首 / 从歌单移除）。
§5 硬约束已落实：同平台请求间隔 ≥1s、429 立即封停不重试、QQ 20279 单独提示、
凭据只进 `safeStorage`（异步 API，无加密后端时宁可不保存）。

细节与**验证到哪一步**见 [`docs/STREAMING-v1-2026-10-17.md`](../docs/STREAMING-v1-2026-10-17.md)。

## 均衡器 / 音效

**十个槽位都是完整参数带**（CR-019）：每段可设**峰值 / 低架 / 高架**、任意频率（10–24000 Hz）、任意 Q（0.1–10）、±12 dB（0.1 dB 步进，引擎侧本来就是连续的）。
默认值仍是 SPEC 3.4 的 31.25 Hz–16 kHz 网格 + Q 1.41 + 峰值，所以既有黄金频响测试逐点不变。

| 能力 | 说明 |
|---|---|
| 内置音色 | 平直 / 暖声 / 人声 / 清晰（十段网格） |
| 目标曲线 | Harman over-ear 2018 / 2015 / 2013、in-ear 2019（来自 AutoEQ `targets/` 的公开 CSV，1 kHz 归一化，拟合误差**显示出来**） |
| 图上拖点 | 横拖改频率、竖拖改增益；与滑杆共用同一条命令队列，不会两套行为 |
| 耳机补偿 | 内置 6 款 AutoEQ 实测预设（HD 600 / DT 770 Pro / K371 / ATH-M50x / Aria / Blessing 2），**含架式滤波与任意 Q** |
| 在线获取 | 输入 AutoEQ 的精确型号名 → 经 gh-proxy 从 AutoEQ 仓库取回，缓存到主进程 `eq-presets.json`（不是 localStorage） |
| 导入文件 | AutoEQ `ParametricEQ.txt` / `FixedBandEQ.txt`、Equalizer APO 配置、CSV 曲线、本项目 JSON |
| 密集曲线 | 超过十个点或纯曲线 → 贪心拟合到十个参数带，并把拟合误差报出来 |
| 外观 | 不支持的指令（低通/高通/`Include`/`Channel`）**列进提示**，不静默丢弃 |
| 房间校正（FIR） | CR-020：载入 WAV 冲激响应做**卷积**校正，带**自动电平归一化**（峰值归 0 dB）、**频响预览曲线**、抽头/声道/采样率/延迟回报；选择持久化在 `eq-ir.json`（只记路径），引擎重启后自动恢复 |

解析与拟合在 `src/shared/eq-preset.ts`（纯函数，有单测）；耳机库与在线获取在 `src/shared/eq-headphone.ts`。

## 歌词

**本地优先，其次在线**（CONTRACT §4.4/§5）。本地：附加文件 → 同名 `.lrc` → `.ttml` → `.yrc`
（**格式按内容判，不按扩展名**）→ `fixtures/lyrics/` 兜底。本地一个字都没有时，主进程才联网：
网易云搜索并计分 → **AMLL TTML DB（CC0，逐字 + 翻译 + 注音）** → 网易云行级（原文 + 中译 + 罗马音）→ LRCLIB。

- 逐字/行级、翻译、罗马音、**逐字注音（振假名）** 都落到 §4.3；`wordByWord=false` 表示行级数据。
- **真字级**来自两处：AMLL TTML，以及网易云 `yrc`（需 weapi 加密接口，明文接口永远没有；中文歌约 3/6 有，日文歌目前没有）。
- **换一个**：列出搜索候选（标题/艺人/时长/计分/风险），用户自己指定这一版；选择记进缓存（`pinned`）。
- **内嵌歌词**：文件标签里的歌词（只收带时间轴的），用应用侧 `music-metadata` 读，不动引擎。
- **行级数据也会逐字填充**：在渲染视图里按字素/词加权插值（契约 §4.3「插值兜底」），标题与底栏如实标「插值」。模型不改、缓存不脏、原生字级照样标「逐字」。见 `src/shared/lyrics-interpolate.ts`。
- 在线取词冷启动 **1.3–2.4 s**（AMLL 档有 2 s 预算 + 连续失败熔断），命中缓存后为 0。
- 命中即缓存（`lyrics-online.json`），**未命中也会记住 7 天** —— 否则「自动查一次」就是每播一次四五个请求。
- 计分低于 0.5 直接放弃并显示「没有歌词」：**错歌词比没歌词更糟**。
- 「纯音乐，请欣赏」这类占位文本会被识别成**结论**（无人声），不是歌词。
- **时间轴自洽校验**：歌词末尾比曲长还多 75 s 的，直接丢弃换下一档（同名翻唱/现场版的元数据可能全对）；轻度过长或覆盖率过低只标风险。
- **保存到本地**：歌词栏「保存到本地」把在线歌词写成音乐旁边的同名 `.ttml`（不覆盖已有文件），之后这首歌本地优先、不再联网。存 TTML 不存 LRC，因为 LRC 装不下「翻译 + 罗马音」两条附加轨，会静默丢掉罗马音。
- 平台级节流（网易云/LRCLIB ≥1.2 s）、`-460` 立即熔断；不使用任何账号凭据。
- 自动取词默认开启，设置 → 本地曲库 可关闭；关掉后只有歌词栏的「在线查找」按钮联网。
- 关键词：「注音」= TTML 的 `<span tts:ruby>`（落到 `word.ruby`）或网易云 `romalrc`（行级 `romanization`）。

完整设计、实测与边界见 [`docs/LYRICS-v1-online-2026-10-17.md`](../docs/LYRICS-v1-online-2026-10-17.md)，
契约侧的追加请求见 **CR-018**（`LyricWord.ruby` 与 `source:'netease-lrc'`，只增不改）。

**两层动效结构（2026-10-15 优化）。** 歌词的「结构」与「填充」由两套机制负责，互不打扰：

| 层 | 谁负责 | 频率 |
|---|---|---|
| 行、词、罗马音、翻译（结构） | React，**只订阅「哪一行是活性行」这一个下标** | 仅换行时（约每几秒） |
| 逐字填充 `--fill`、current/sung 类名 | 画笔（`lyricPlayhead` + ref 直接改 DOM） | 显示刷新率 |

之所以要拆开：引擎的 `position` 实测约 **9–10 Hz**，按事件跳变时一个字（350ms）中间只落 2–3 格 —— 肉眼就是一顿一顿；
而如果改成每帧重渲染，长歌词下每秒会 diff 上千个节点。所以填充走补间 + 直接改 DOM，
React 那边用**返回值是下标的快照**（`activeLineIndex`）保证同一行内的事件不会唤醒它。

补间遵守项目自己的两条规矩：**可以轻量补间，但必须能被真实状态纠正**（REFS-B-app）——
新事件一到**直接对齐**，不做平滑追赶（那会引入滞后）；**数字不外插**（时间/进度仍取权威值）。
事件迟到超过 400ms 就**冻结**，宁可停住也不谎报已经唱到哪。**减少动态效果时不跑补间**
（DESIGN-v4：形变→瞬时切换、不插值），只按事件落格，位置依然准确。

**逐字填充（REFS-B2 §2.6）。** 当前字不是「到点整词换色」，而是一条按音频位置推进的连续填充：
渐变的边界停在 `--fill`（0–1，由 `src/renderer/src/lyricFill.ts` 从引擎位置算出），并被裁到字形本身。
**按已测量的字形宽度插值，不按字数均分** —— 而且这里的「测量」就是排版引擎给出的词盒宽度，
不再用 `canvas.measureText()` 另量一份：再量一份会与真实排版漂移（字体回退、字距、kerning），
比不测量更糟。词的切分在 `lrc.ts` 里按标签下标进行，组合字符（如 `e` + U+0301）天然留在同一个词内，
不做任何按 code point 的切分。

**空格属于排版。** 词级歌词里「下一个标签前的空格」会留在前一个词的字形里 ——
旧实现给每个词段做 `.trim()`，把 "…增强LRC<00:35.80> word" 渲染成了 "增强LRCword"：
中文段落看着还凑合，中英混排直接把单词粘在一起。现在有断言钉住
**`words.join('') === line.text`**（逐行、两个 fixture）。

## 音乐空间与音效

首页左列为封面/3D 唱片叠层与短 EQ 曲线，右列为当前曲目和独立滚动的歌词。切歌时封面与唱片成组退出/进入，结束后释放旧场景。曲库可切换歌曲列表与艺术家瀑布，点击艺术家筛选歌曲。沉浸播放保留独立歌词阅读与底部完整控制。唱片仅在播放或指针交互时连续更新；不可见、文档隐藏或减少动态效果时停止动画，WebGL 不可用时显示唱片回退图形。

封面优先读取用户选图，其次是文件嵌入封面、同目录同名图片、`cover`/`folder`/`front` 的 JPG/PNG。悬停封面后可点「添加封面/更换封面」，映射保存在 Electron `userData/artwork.json`，不改音乐文件。选图限制 8 MB、边长 8192、总像素 3200 万；真实解码验证后最大缩到 1024px。缺少图片时显示明确标注的曲目字形视觉。本地参考库 91 首均没有嵌入封面，因此不会凭空显示唱片公司的专辑图片。

顶栏「随曲主题」控制从实际封面提取的主题色；无封面时使用稳定的曲目配色。它影响音乐背景、进度和 EQ 强调，C1 告警和 C2 信号语义颜色保持独立。偏好写入本地存储。

播放栏有静音/恢复原音量、信号路径和「播放详情」。详情分开显示音源格式/码率/大小与设备输出格式、容器/有效位、设备周期、DSP、欠载和实时进度；未知字段显示空缺，断连时清理旧遥测。`state.bitDepth` 是源位深，输出位深读取 `containerBits`/`validBits`。原生队列在手动播放前同步，上一首/下一首可实际切歌。

音效页提供十段 EQ、预设、Q、前级增益和自动余量。曲线根据**引擎已确认**的参数，使用浏览器原生离线双二阶滤波器计算稳态频率响应；浅线是有限的参数历史轨迹。曲线不表示正在播放的音频样本或实时 FFT，限幅与削波也不包含在内。引擎未提供完整参数、设备采样率或离线滤波器时，会显示原因而不生成虚假曲线。

`pnpm test:player` 的截图与结果写到 `.smoke/player/`；真实引擎可通过 `TWILIGHT_ENGINE` 指定。该测试用独立配置目录检查选图，测试图片明确印有 ARTWORK TEST，不写入正常封面配置。该测试播放时音量为零，但 `test:integration` 的播放断言会短暂出声。

## 环境坑（本机实测，已踩平）

- pnpm 11 的构建白名单/镜像配置在 `pnpm-workspace.yaml`（package.json 的 `pnpm` 字段被忽略）；
- Electron 二进制 0 字节占位（postinstall 静默跳过）→ 进 `node_modules/electron` 手动
  `node install.js`（配 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`）；
- 自动化 shell（DSH pwsh 等）宿主可能带 `ELECTRON_RUN_AS_NODE=1`，会让 electron.exe 变纯 Node
  （报 `electron.app` undefined）——启动前清掉；主进程 spawn 工具型子进程时反而要显式设它。
