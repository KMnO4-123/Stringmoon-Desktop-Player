# v3 需求规格（2026-10-18）：底噪/爆音治理 + 空间音频 + 全局搜索接入 GD 音乐台/Embeat + 播放队列与视图

> 用户原话：「解决播放暂停和切歌的时候的噪声，电流声问题。加入杜比音效，可参考cavern等引擎，并优化转化为更高效的方式实现。还有全局搜索融入 https://music.gdstudio.org/ 和 https://github.com/gdstudio-org/Embeat 的方案。整合好。同时加入播放队列功能，以及按歌单，按队列，按文件夹和调整播放顺序等等。我的歌曲要能按文件夹区分。」

## 0. 已完成的现场勘测（Lead，可复现）

### 0.1 GD 音乐台 API（已实测可用）
- 端点：`https://music-api.gdstudio.xyz/api.php`（web 页面 ajax.js 还给出 `music-api-cn/hk/us` 镜像）。
- 搜索：`?types=search&source=netease&name=<kw>&count=N&pages=1` → `[{id,name,artist[],album,pic_id,url_id,lyric_id,source,from}]`。
- 取链：`?types=url&source=netease&id=<url_id>&br=320`（省略 br = 最高）→ `{url,br,size,from}`；实测拿到 flac 918k / mp3 320k 且为 126.net 直链。
- 歌词：`?types=lyric&source=netease&id=<lyric_id>` → `{lyric,tlyric}`；封面：`?types=pic&source=netease&id=<pic_id>`。
- 歌单：`?types=playlist&source=netease&id=<id>` → 网易云原始 `{code,playlist:{tracks...}}`（需适配）。
- 可用源实测：`netease` ✅、`joox` ✅（部分歌无链）；`tencent/kugou/kuwo/...` 在本机网络下失败（需在实现里做“源可用性探测 + 失败换源”而不是写死）。
- **Embeat 集成方式**：主站公告明确「Embeat音乐源…能与 Embeat 相似歌曲功能完美匹配(Beta)」；api 参数为 `types=embeat_by_track`（在 ajax.js 里出现），当前对无鉴权请求返回 4xx/5xx，**本轮按“相似歌曲推荐”能力实现：/similar 走 embeat_by_track，失败则降级为 GD 自身相关搜索**（不假装成功）。

### 0.2 Embeat（GitHub）定位
- 仓库自述：item-to-item 音乐推荐系统（Spotify 45M tracks / 1.8M playlists 训练，输入 track id/ISRC → 相似歌曲），MLP/embedding + checkpoint（`checkpoints/`），有 `infer/` 与 `eval/`。
- 结论：**它不是一个搜索源**，是“相似歌曲/推荐”的模型服务。本轮接入 = ①以 `types=embeat_by_track` 优先拿相似曲目；②拿不到时用本地曲库的 artist/album 相关曲目兜底。**不**在客户端塞 PyTorch 推理。

### 0.3 播放噪声的现有机制（已读代码）
- 已有：`AudioFade`（线性 5ms，`kPlaybackRampMs`）、`fadeOutBeforeStop()`（暂停/停止/切歌前淡出并等设备排空）、`volumeGain_`（10ms 增益斜坡）、`beginFadeOut/beginFadeIn`、TB 级 `fadeDrainPending` 排空确认、xrun 检测。
- **爆音源（独立验证者逐条核对代码后的结论，2026-10-18 修订）**：
  1. ✅ **真因：`seek()` 在播放中无淡出**（`player.cpp:1196-1198` 直接 `output_.stop()`；对比 `openSourcePath`/`pause`/`stop` 都有 `fadeOutBeforeStop()`）→ 跳转瞬间硬切。
  2. ✅ **真因：播放中修改重采样器配置无淡出**（`player.cpp:474` 改设置即重建链路）。
  3. ✅ **真因：解码失败 `handleInputFailure` 直接 `stop()`**（`player.cpp:211-215`），错误路径硬切。
  4. ✅ **真因：排空 deadline 超时后硬停**（`player.cpp:366-370`）；正常路径不会，但设备事件流卡顿时会走到。
  5. ✅ **质量不足：线性 5ms 曲线**（`audio_fade.hpp:8`）—— 线性淡出在中途仍有可闻台阶；应改等功率（sin²）并可配 8–15ms。
  6. ✅ **端点切换底噪（环境类）**：USB DAC / 蓝牙在 `stop()/start()` 之间的电源与时钟切换本身有底噪 → `pauseHold`（暂停保持流打开、渲染静音）是解法。
  7. ❌ **已撤回（原假设不成立）**：「切歌尾巴没被设备播完」——`fadeOutPending` 的清除条件是 `endpointProgress_.drained()`（`output_wasapi.cpp:919-926,1108-1113`，要求 device played ≥ lastAudioEnd，即 padding=0）。
  8. ❌ **已撤回**：「独占 `Stop()` 前未 `Reset()`，残留缓冲被重放」——seek/open/resampler/设备变化都走 `resetStream()`（`player.cpp:1076`、`resetSourcePosition:551-558`）再 `Start()`。
- **结论**：修 seek / 重采样器变更 / 输入失败三处淡出 + `pauseHold` + 等功率曲线 + 排空超时兜底；并暴露结构性计数（`state.fade` 里加 `lastTransport{paddingAtStop, fadeCompleted, resetBeforeStart}` 与 `fadeDrainTimeouts`）供自动断言（独占/蓝牙无 loopback 时只能靠它）。
- **自动断言方案（独立验证者设计）**：扩展 `engine/tools/capture-loopback.ps1` 采集统计 JSON（断流间隙、断流前最后样本、断流后首样本、连续段 maxΔ、RMS 包络）；48k/997Hz/-20dBFS 合成音 + shared 模式，一次 12s 覆盖 16×pause/resume + 16×seek + 切歌/stop；阈值：正常 maxΔ = A·2πf/fs ≈ 0.013，硬切判据 |last|/A>0.1 且 maxΔ>0.052。必须用旧引擎做 A/B 证明判据灵敏度。

## 1. 目标与验收

### 1.1 暂停/切歌噪声（P0）
- 修法方向（按效率排序）：
  a. **Fade 曲线改为等功率（sin²/余弦）**，从线性 5ms 提到 8–15ms 可配置；线性淡出在中途仍有可闻“台阶”。
  b. **暂停不硬停流**：新增 `pause-hold` 状态——淡出到 0 后保持 stream 打开、渲染静音（`silence_=true` 但线程继续跑），恢复时 `fadeIn` 而不 `Start()`；只有 stop/切歌才真正 `Stop()`。
  c. **切歌零硬切**：淡出后等 `endpointProgress_.drained()`（设备 buffer 真正播完），再 `Stop()+Reset()`；`Reset()` 必须在 `Stop()` 后、`Start()` 前。
  d. **seek 也淡出**（短 5ms）或直接走 `pause-hold` 的静音窗口。
  e. 可选：`set_output` 增加 `fadeMs`（0–50，默认 10）与 `pauseHold`（默认 true），协议只增。
- 验收（可自动断言）：用 loopback 录制的 **静音段 RMS** 与 **相邻样本最大跳变**（Δ）在 pause/resume/切歌/seek 四个场景低于阈值；引擎侧 selftest 增加“fade 曲线首尾连续、等功率校验”；人工听感 5 次以上（owner）。

### 1.2 杜比音效 / 空间音频（P1，不照搬 Cavern）
- 参考 Cavern（开源 C# 空间音频引擎：HRIR 卷积、交叉馈送、上混/下混、对象渲染）与 Dolby Atmos 的基本链路：**Bed + Object → 声道映射 → HRTF/串扰消除 → 上混/下混均衡**。
- **本项目的高效实现路线**（不引入 .NET/C# 运行时、不装第三方引擎）：
  1. 复用已有 **partitioned FFT 卷积器**（`convolver.hpp`，1024 帧分块）做 HRIR/串扰消除——这是 ECHO NEXT 移植时已完成的 IR 基础设施，零新增依赖。
  2. 新增 `spatial` 模块（引擎侧 DSP 阶段）：
     - `mode: 'off' | 'crossfeed' | 'wide' | 'virtual'`（crossfeed=耳机串扰消除；wide=中侧立体声扩展；virtual=HRIR 虚拟环绕，仅对立体声上混）。
     - 参数：`amount`(0–1)、`azimuth`(±90°)、`hrir`（内置 24 个方位 IR，44.1k 采样、生成/内置均可）、`delayMs`（ITD 0–1ms）。
     - 只用 **双耳（2ch）** 输出，不引入多声道设备协商（避免 WASAPI 多声道兼容坑）。
  3. 效率约束：RT 路径零分配、卷积在频域、HRIR 24 方位预转频谱（启动算一次）、上混只做一次 2→2 矩阵。
  4. 默认 `off`（听感不变、bit-perfect 语义不变）。
- 验收：`--selftest` 数学断言（crossfeed 低频能量守恒、virtual 的左右串扰 ≥ 阈值、off 逐样本恒等）；e2e 设置页可切；人工听感（owner）。

### 1.3 全局搜索接入 GD 音乐台 + Embeat（P1）
- 新增 provider `gdstudio`（本地主进程 HTTP，不走外部进程）：`main/streaming/gdstudio.ts`
  - `search(keyword, source)` → 归一化为现有 `StreamingTrack`。
  - `resolvePlay(track)` → `types=url` 取链；**失败自动换源**（netease→joox→embeat），返回真实 `br/format`。
  - `lyrics(track)`、`cover(track)`、`playlist(id)`。
  - 源可用性探测（启动/首次使用时，缓存 10 分钟），界面如实显示“哪个源当前可用”。
- 全局搜索融合：`searchAll` 增加 gdstudio provider，结果按 source 分组（本地 / 网易云 / QQ / GD音乐台 / Embeat 相似）。
- Embeat 相似：`similar(track)` → `types=embeat_by_track`；失败降级为 GD 源内同歌手/同专辑搜索，并在 UI 标注“推荐降级”。
- 验收：单测（XML/JSON 形状、换源、失败降级、缓存）+ e2e（搜索出 GD 结果、能播放、能看歌词）+ 手动联网冒烟（真实 API）。

### 1.4 播放队列 + 四种视图 + 排序（P0）
- 引擎已有 `set_queue/next/prev/repeat/queueIndex`；本轮补：
  - **播放队列面板**（新视图或右栏抽屉）：当前队列、当前项高亮、拖拽排序、删除单项、清空、“下一首播放/追加到末尾”。
  - **按歌单**：已有本地歌单 + 平台歌单，队列可从歌单整体生成。
  - **按队列**：队列即视图（与播放列表同源）。
  - **按文件夹**：新视图——`library` 视图增加“文件夹”分组维度（用曲目绝对路径的目录层级），可逐层展开/进入，可整目录加入队列/播放。
  - **排序**：队列内可拖拽 + “按文件夹/按歌名/按歌手/按时长/按添加顺序”排序（仅影响队列顺序，不改文件）。
- 数据：`queueIds` 已在 store；需持久化（已有 playback-memory 含 queue，可复用）。
- 验收：单测（排序/插入/去重/持久化）；e2e（建队列→拖拽→下一首→切视图→文件夹视图）；性能（1000 首队列操作 < 16ms/次）。

## 2. 非目标
- 不在客户端内嵌 PyTorch/Embeat 模型推理；不做 Dolby Atmos 商业解码；不做多声道/HDMI 直通（本轮只双耳）；不做 DLNA/UPnP。

## 3. 依赖与风险
- GD 音乐台为第三方站点：随时可能限流/改协议 → 必须做“源不可用”的诚实降级与缓存，不阻塞本地播放。
- `joox` 源部分曲目无链；`embeat_by_track` 需鉴权时降级。
- 噪声修复需真机听感确认；自动化只能证明“无硬切/无未排空残留”。
