# 去爆音：切歌/暂停/播放的电流声（v6.5，2026-10-18）

> **状态**：引擎已修 + 离线/静音验证全绿；真机听感待你确认。
> **上位**：`docs/LOGIN-DEVICE-v6-4-2026-10-18.md`
> 用户：「切歌，暂停，播放时会有电流声和噪声」。

## 1. 根因（有基线证据）

`--probe-transport` 基线（修复前）：

```
stop   paddingAtStop=0 fadeCompleted=1 ...
seek   paddingAtStop=0 fadeCompleted=1 ...
switch paddingAtStop=0 fadeCompleted=1 ...
```

1. stop / seek / 切歌只做 **5ms 淡出**，且淡出归零后**立刻 Stop/Reset/Close**：
   端点缓冲里没有确定的静音，独占驱动截断硬件缓冲 → 就是听到的「咔 / 电流声」。
   `paddingAtStop=0` 正是这个窗口。
2. pause-hold 可能在**最后一块仍有数据**时冻结（同样会在恢复瞬间爆音）。
3. 恢复路径 fadeIn 起点本来就是 0（sin² 首帧 = 0），检查后无需改动。

## 2. 改动（仅 engine/src）

| 文件 | 内容 |
|---|---|
| `output_wasapi.hpp/.cpp` | `kTransportFadeMinMs=15`、`kStopSilencePadMs=15`：渲染线程淡出归零后**继续写 15ms 静音**，等设备播到提交水位才置 `fadeActive=false`（pause-hold 同路径先补静音再冻结）；`TransportTrace` 增 `silencePadFrames` |
| `player.cpp` | stop/seek/切歌/换 resampler/读失败/暂停的淡出下限 → 15ms；排水 deadline 计入 padding；超时双计数；`state.fade.lastTransport` 增 `silencePadFrames` |
| `probe_transport.cpp` | 离线模型同步静音 padding；`paddingAtStop` 语义 = 停流前补的静音帧数；188 条断言（last/first=0、padding>0、hold 缓冲全 0、无采样级台阶、曲线非线性） |
| `endpoint_progress.hpp` | 暴露提交水位供静音排水判据用 |

## 4. 软件边界

- USB DAC 在 Stop/Start 时的**电源声/继电器声属驱动层**，软件只能靠淡出 + 15ms 静音规避；
- 切歌若改变采样率（44.1↔48↔96）独占流必须重开，设备自身重配置的「咔」无法完全消除；
- 想彻底避免换格式爆音，可把输出采样率固定为设备格式（用 SoXR 重采样）——这会牺牲
  「跟随源」的 bit-perfect，需你决定是否要这个取舍。
