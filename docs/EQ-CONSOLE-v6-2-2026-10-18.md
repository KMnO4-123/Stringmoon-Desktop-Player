# EQ 调音台控制台重做（v6.2，2026-10-18）

> **状态**：现行 · **日期**：2026-10-18 · **给谁**：owner / 下一轮接手者
> **上位**：`docs/HIFI-KEEPALIVE-v6-2026-10-18.md`、`docs/AUDIO-CONSOLE-v5-2026-10-18.md`
> 用户先反馈「均衡器有问题，你把控制台给压缩了」，随后明确「要之前那种调音台模式」。
> 本轮把 EQ 完整编辑器恢复成**十路竖向推子并排的调音台**，并把每路的频率/Q/类型变成一等控件。

## 1. 根因：竖向推子为什么一直被压成 22px

v5 起音频控制中心的外壳样式里有：

```css
.audio-console input[type='range'] { width: 100%; height: 22px; }
```

它的权重是 **c=2（class + 属性选择器）, d=1（input）**；而 `.eq-band-slider` /
`.eq-channel-fader` 只是 c=1。所以无论写 `height: 112px` 还是 `200px`，**竖向推子都被改写成
22px 高的横条** —— 这就是「控制台被压缩」的直接来源（不是布局列宽的问题）。

修复：选择器必须写成 `.audio-console input.eq-channel-fader[type='range']`（c=3, d=1），
并在注释里写明这个权重陷阱，避免下一轮又「顺手简化」掉。

## 2. 调音台布局（用户要的那种）

```
.eq-console            grid: 44px dB 刻度 + minmax(0,1fr) 台面
  .eq-console-scale    +12 / +6 / 0 / −6 / −12 与推子行程对齐
  .eq-console-bank     grid: repeat(10, 1fr)，10 路通道并排
    .eq-channel        序号 / 增益读数 / 200px 竖向推子（居中 0 dB 中线）
                       / 频率(Hz) 数字输入 / Q 数字输入 / 类型 / 复位
```

- 推子 200×26px（旧版 112×20，且实际被压成 22px 横条）；通道宽约 88px（1280 下）；
- 0 dB 中线常显，推子**双击回 0 dB**；
- 窄于 1100px 时十条通道允许横向滚动，而不是把每条压到 40px 以下；
- 频响图保持 320px（v6.1 已抬起）。

## 3. 每路独立可调（频率/Q/类型）

和 v6.1 相同的协议语义，只是换成了通道形态：

| 控件 | 行为 |
|---|---|
| 推子 | −12..+12 dB，step 0.1，实时下发 `bandGains[i]`，双击回 0 |
| 频率 | 20–20000 Hz 数字输入，回车/失焦提交，下发 `bands[i] = {freq}` |
| Q | 0.1–10，提交下发 `{q}` |
| 类型 | 峰值 / 低架 / 高架，下发 `{type}` |
| 复位 | `{freq: 0, q: 0}` = 回到该路工程网格频率与全局 Q |

每次只带 `index+1` 长度的索引对齐稀疏补丁，调一路不会回写其它九路；
图上拖动（横拖频率、竖拖增益）与推子/输入改的是同一份状态。

## 6. 诚实边界

- 「复位」清的是**该路形状**（频率/Q），不改增益；增益归零走工具栏「归零」或推子双击。
- 通道推子是线性的 −12..+12 dB（不是调音台的 dB 对数行程）；0 dB 在正中。
- 设备采样率低于 2×某路频率时该路被引擎保持直通，界面置灰并写明原因。
