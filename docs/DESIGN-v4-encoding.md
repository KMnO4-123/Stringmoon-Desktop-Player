## 0. 先纠正前两份方案错在哪

| 我做的 | 为什么错 |
|---|---|
| 抄 Nothing 的**黑底 + 点阵字 + 红点缀 + 网格线** | 这些是**产物**，不是系统。照抄产物 = 得到一套看起来像 Nothing 但不会生长的皮肤 |
| 上一版把 Nothing 总结成"五条主导原则"（信息坦诚/双字体/工业网格/单色/工程形态） | 那仍是**外观清单**。真正的系统设计是**规则**：什么进哪个通道、怎么保证不撞车、加新状态时怎么办 |
| 我说"信号路径是本方案记忆点" | 方向对了一半。信号路径是**一个实例**，不是**系统本身**。它该从规则里推导出来，而不是被设计出来 |

**Nothing 的系统设计内核是这一句**：

> **Glyph 是一盏灯。它只有亮/灭/节奏。** 在这个极小的输出空间里，Nothing 建立了一整套**信息编码方案**——什么信息值得占用这盏灯、用几种模式表达、如何保证两个状态不会长得一样。

**这才是可移植的东西。** 音乐播放器的"Glyph"不是 LED 灯，而是**三个有明确表达力上限的通道**。

## 1. 系统设计第一原则：约束驱动（不是审美驱动）

Nothing 的每一次设计决策都来自**技术约束**，不是审美偏好：

| Nothing 的约束 | 推导出的设计 |
|---|---|
| LED 只有亮/灭，数量有限 | 用**节奏与位置**编码，不用颜色 |
| 手机背面不能被看见 | 用**光的模式**通报，不用屏幕 |
| 透明后壳暴露内部 | **内部本身就是设计**，不必掩盖 |
| 信息密度需求 | **Micrographics**：用图形而非文字承载数据 |

**翻译到 Twilight Echo——你的约束是什么？**

| 你的真实约束 | 推导出的设计（本方案的全部依据） |
|---|---|
| **数字遥测丰富**：`bitPerfect`/`resampled`/`bitDepth`/`xrunCount`/`periodMs`/`sourceSampleRate`/`exclusiveFormats` | 必须有一个**高密度图形通道**，否则这些数据只能变成一堆小字 |
| **用户是"要听出差别的人"**（你有 Sonar + ASV + 91 首 24bit FLAC） | 状态必须**可信且不可美化**——设备做不到就如实说 |
| **bit-perfect 在本机根本走不通**（实测：驱动不触发缓冲区事件） | **降级是常态**，不是异常。界面必须让"降级"看起来理直气壮，而不是一个错误 |
| **播放是长时段、低注意力的活动** | 主状态必须**余光可读**（不盯着看也能知道在播/没播） |
| **键鼠 + 大屏**，非触屏 | 有 hover、有精确指针、有空间画布 |

**这四条约束直接决定了下面的三通道体系。**

## 2. 通道预算：三个通道，各自的表达力上限

Nothing 的系统设计里，Glyph 的**表达力是被刻意限制的**——正因为受限，它才必须把信息压缩到极致，从而获得"不看不打扰、一看就懂"的性质。

**你的界面也有三个通道，每个都有硬上限：**

| 通道 | 对应 Nothing | **表达力上限（硬约束）** | 感知方式 | 判定问题 |
|---|---|---|---|---|
| **C1 光** | Glyph LED | **≤ 6 种可区分模式**。只能用：亮/灭、呼吸/静止、快/慢、单点/多点 | **余光**（pre-attentive） | "不盯着看能知道吗？" |
| **C2 形** | Micrographics | **只能用几何与计数**：点、格、线、角度、填充量。**不得出现文字** | 扫视（1 秒内） | "看懂它需要读字吗？" |
| **C3 字** | 屏幕正文 | 完整语义，**但需要注视** | 注视（foveal） | "这是内容还是状态？" |

### 2.1 三条通道纪律（这是系统规则，不是建议）

**规则 R1 — 归属唯一**
> 每个状态**必须**在 **C1 或 C2 中被完整判定**。C3 只允许补充细节，不允许独家承载语义。

**规则 R2 — 禁止跨通道冗余**
> 同一信息不得在 C1 与 C2 以**相同语义**重复表达。跨通道只允许**互补**（C1 给"有没有问题"，C2 给"问题是什么"）。

**规则 R3 — 通道降级必须无损语义**
> C1/C2 不可用时（`prefers-reduced-motion`、高对比模式、色盲），状态必须在 **C3 中仍然完整**——即降级路径是**预先设计**的，不是事后补的。

> ⚠️ **R1 的检验方法**：把界面截图**糊成马赛克**。如果这时无法判断"在播放吗 / 音质有没有问题"，R1 就被违反了。

## 3. 状态编码表（本方案的核心交付物）

**下表穷举了 `protocol.ts` 里的全部状态。** 每个状态一条，不得有遗漏——**完整性是"系统"与"风格指南"的分界线**。

### 3.1 播放主状态（C1 承载）

| 状态 | 来源 | **C1 光** | C2 形 | C3 字 |
|---|---|---|---|---|
| **无曲目** | `playState: 'no-track'` | **全暗**（无任何发光） | 空轨道 | — |
| **已装载未播** | `loadedTrackId` 有值、未播 | **单个常亮点，低亮度** | 静止点阵 | 曲名 |
| **播放中** | `state: 'playing'` | **呼吸**（周期 4s，亮度 0.5↔1.0） | **流动**（光点沿路径移动） | 曲名 + 时间 |
| **暂停** | `state: 'paused'` | **常亮，不呼吸** | 静止，当前格高亮 | — |
| **加载中** | `playState: 'loading'`（intent 在途） | **扫描**（亮点从左到右，2 次/秒） | **逐格填充** | — |
| **Seek 中** | `seekPending: true` | 扫描（更快，3 次/秒） | 目标格闪烁 | 目标时间 |
| **自然播完** | `ended: 'eof'` | 呼吸→**一次长淡出** | 全格填满 | — |
| **已停止** | `state: 'stopped'` | 同「已装载未播」 | 静止 | — |

> **C1 只用四种模式就覆盖了全部播放状态**：全暗 / 常亮 / 呼吸 / 扫描。
> 这就是"受限通道"的价值——**四种模式，零歧义**。

### 3.2 音质状态（C2 承载 —— 这是本系统的灵魂）

**这是 Nothing 的 Micrographics 精神最需要落地的地方**：你的引擎能报 8 个音质相关的值，它们**不该变成 8 行小字**。

**C2 的编码语法——一条"信号路径"上的四段：**

```
   [解码] ── [源率] ── [转换] ── [输出]
      ●         ●         ○         ●
```

| 段 | 编码方式（纯几何） |
|---|---|
| **解码** | 实心方 = 已解码；空心方 = 未装载 |
| **源率** | **竖线的高度**表示采样率（44.1k 矮 / 96k 高 / DSD 最高） |
| **转换** | **直线 = 直通**；**折线（∧）= 发生重采样**（几何即语义） |
| **输出** | **实心圆 = 独占**；**空心圆 = 共享**；**圆+括号 = 蓝牙** |
| **位深** | 段下方的**格点数**（16 → 4 格 / 24 → 6 格 / 32 → 8 格） |
| **bit-perfect** | 整条路径**连成一条不中断的实线** = BP；**任一处虚线/折线 = 非 BP** |

**这套编码的三个性质**（检验它是不是"系统"）：
1. **无文字** — 满足 C2 的硬上限
2. **几何即语义** — 折线真的表示"被弯折过"，虚线真的表示"有中断"。**不是图标约定，是图示**
3. **可组合** — 新增一个处理环节（M2 的 EQ/RG）就在中间插一段，语法不变

#### 3.2.1 音质状态的完整判定表

| 引擎报告 | C2 图示 | C3 文字（补充，非承载） | C1 |
|---|---|---|---|
| `bitPerfect: true` | `●─│─│───●`（连续实线） | `独占 · 96k/24bit` | 稳定 |
| `resampled: true` | `●─│─∧─│─●`（折线） | `44.1k → 48k 重采样` | 稳定 |
| `outputMode: 'shared'` | `●─│───○`（空心圆） | `共享模式` | 稳定 |
| `degradeReason` 存在 | `●─│─┄┄─○`（**虚线**） | **降级原因** | **琥珀慢闪** |
| `isBluetooth` | `●─│──(○)` | 设备名 | 稳定 |
| `xrunCount > 0` | 路径上一处**抖动标记** | `xrun N` | **瞬时抖动** |
| 错误 | 路径**断开**（缺口） | 错误码 + 原因 | **红 + 急闪** |

> **`degradeReason` 用虚线而不是红色** —— 这是本系统最重要的一条设计决策。
> 你的机器**永远无法 bit-perfect**（驱动限制）。如果降级 = 红色 = 错误，界面就**永远在报错**。
> **虚线表达"这条路是通的，但中间有东西经过"——诚实，且不制造焦虑。**
> 红色只留给**真正失败**（`ERR_DEVICE` / `fatal`）。

### 3.3 设备与系统状态

| 状态 | 来源 | C1 | C2 | C3 |
|---|---|---|---|---|
| 引擎未连接 | `engineUp: false` | 全暗 | 空 | `connecting…` |
| 引擎就绪 | `ready` 事件 | 单点常亮（低） | 一段实线 | `engine ready · vX` |
| 扫描中 | `scan_progress` | 进度光 | **逐格填充**（N/M） | `扫描 40/91` |
| 扫描完成 | `scan_done` | 一次闪亮 | 满格 | `曲库就绪 · 91 首` |
| 设备切换 | `device_changed` | 一次闪亮 | 路径重绘动画 | 新设备名 |
| 无独占能力 | `hasExclusive: false` | — | 输出段**只能画空心** | `本设备不支持独占` |
| 独占格式受限 | `exclusiveFormats: ["48000:16"]` | — | 源率段**被框住** | `仅支持 48k` |
| 命令在途 | `pendingRequests > 0` | 顶栏一点脉冲 | — | — |
| 协议错误 | `protocolError` | 红急闪 | 路径断开 | 完整错误文本 |

### 3.4 能力自报（`EngineCapabilities`）

**这是"透明后壳"最直接的落地**：引擎自己说它能做什么。

| 能力 | 表达 |
|---|---|
| `exclusive: true` | C2 输出段可画实心圆 |
| `exclusive: false` | 输出段**永久空心**（**不是错误，是事实**） |
| `resampler: true` | 转换段可画折线 |
| `dsp: true` | 路径中可插入 DSP 段（M2 后） |

> **界面只画引擎声明支持的东西。** 引擎没说的能力，界面不假装有——这是 Nothing「不伪装」的系统约束。

## 4. 加新状态的规则（系统能生长的证明）

**一个新功能加进来时，必须按这四步走。** 这是"系统"与"皮肤"的根本区别——**皮肤靠审美判断，系统靠流程**。

```
第 1 步  这个状态必须被感知吗？
        否 → 只进 C3（大多数内部状态）
        是 → 继续

第 2 步  它是「有没有异常」（二值）还是「是什么」（有结构）？
        二值 → 归 C1
        有结构 → 归 C2

第 3 步  C1：在现有 4 种模式（全暗/常亮/呼吸/扫描）里选一个。
        ★ 如果 4 种都不够用 → 停下，这是系统要扩容的信号，不是随手加颜色
        C2：它能在现有语法（点/格/线/角度）里表达吗？
        ★ 不能 → 定义新的几何基元，并更新 §3.2 的语法表

第 4 步  检查 R1/R2/R3：糊成马赛克还能判定吗？和已有状态撞车吗？禁用动效后还完整吗？
```

**示例——M2 加入 EQ 后：**

| 问题 | 答案 |
|---|---|
| EQ 开启要不要感知？ | **要**（它破坏 bit-perfect） |
| 二值还是结构？ | 二值（开/关）——但**它破坏 bit-perfect**，所以归 C2 |
| C2 怎么表达？ | 在转换段与输出段之间**插入一段**，用**波浪线**表示"信号被改过" |
| 检验 | 折线（重采样）+ 波浪线（EQ）可同时出现，语法不冲突 ✅ |

```
●─│─∧─～～─○     重采样 + EQ + 共享输出
```

**语法没变，只是多加了一种线段。** 这就是系统成立。

## 5. Apple 层：光感 / 动效 / 交互（物理）

Nothing 给了**编码**，Apple 给**物理**。两者分工明确：**Nothing 决定"是什么状态"，Apple 决定"状态之间怎么过渡"。**

### 5.1 光感（Apple §12 材质 + §13 因果）

| 光的用途 | 规则 | 依据 |
|---|---|---|
| **呼吸光**（播放中） | 周期 **4s**，亮度 0.5↔1.0，`ease-in-out`。**不用正弦**（正弦在极值处太慢） | 北欧：慢即安静 |
| **扫描光**（加载中） | 2 次/秒，`linear` | 恒定运动用 linear |
| **状态切换闪光** | 200ms，`--ease-out-strong` | Apple：反馈要即时 |
| **氛围光**（封面取色） | 播放时 `opacity 0.55`，暂停 `0.28`，过渡 600ms | Apple §13：反馈与因果同帧 |

**一条硬规则（Apple §13 因果性）**：
> **光的每一次变化必须由真实事件触发**（state / xrun / device_changed / scan_progress）。
> **不得有"为了好看"的循环动画**——这与 R1「状态必须可判定」冲突：无因果的光会稀释 C1 的信噪比。

### 5.2 动效（Apple §3 可打断 + `animate` 频率门控）

| 交互 | 频率 | 决定 |
|---|---|---|
| 空格/←→ | **100+/日** | **零动画** |
| 列表 hover | 数十次/日 | 仅颜色，**无位移** |
| **C2 路径的几何形变** | 切歌/切设备时 | **动**（这是最有价值的动效） |
| C1 模式切换 | 每次状态变化 | **不插值**——光只有亮/灭，**跳变**才符合它的物理 |

**C2 的形变是本方案最重要的动效**：

```css
/* 采样率变化：源率竖线的高度用弹簧，不是缓动 —— 它像一根被拨动的弦 */
.sig-bar-src {
  transition: height 380ms var(--ease-immerse);
}
/* 直通↔重采样：直线变折线，用 stroke-dashoffset + path 变形 */
.sig-path-seg {
  transition: d 420ms var(--ease-in-out-screen);
}
```

**Apple 的投影函数用于路径光点**（§6 的 `project()`），使光点在 seek 后的落点符合动量直觉。

### 5.3 交互（Apple §2 直接操纵 + §9 橡皮筋）

**唯一需要复杂手势的地方是进度条**：

| 环节 | 做法 |
|---|---|
| 抓取 | `setPointerCapture` + **尊重抓取偏移** |
| 拖动 | 1:1 跟随，**时间码持续反馈** |
| 边界 | **橡皮筋**（拖过端点渐进制动，不是硬停） |
| 释放 | **速度投影**决定落点 |
| 打断 | 从**当前显示值**继续，不从目标值 |

**其余交互遵守「Nothing 的仪器按钮」纪律**：
- 按下反馈用**变亮**（`rgba(255,255,255,0.07)`），**不用 `scale`** —— 仪器按钮不缩
- **焦点环固定高对比白**，**不得用强调色**（浅色封面上会消失）

## 6. 北欧层：空间与材料（它擅长的，且只做这个）

北欧在这里**不参与造型**（这是上一版的错误），只负责两件它真正擅长的事：

### 6.1 空间（留白是信息层级，不是风格）

| 规则 | 做法 |
|---|---|
| **间距表达归属** | 同一信息组内 `4px`；组间 `16px`；区段间 `40px`。**用空白分组，不用线框** |
| **一屏一个重心** | 播放中 → 重心在 C2 路径；浏览中 → 重心在列表。**不得同时两处发光** |
| **网格只用于数据对齐** | 列表轨道对齐（`64px | 1fr | 240px | 72px`），**不画装饰性网格线** |

> **撤销上一版的"工业网格线"**：Nothing 的网格是**硬件结构**（真实存在的电路板栅格），不是画的线。
> 在软件里画满网格线 = 模仿它的**产物**。**只保留数据对齐用的隐式轨道。**

### 6.2 材料（漫射光，无方向性）

```css
/* 唯一的"材料"是氛围光：无方向、低对比、缓慢 —— 北欧的光 */
.ambient {
  background: radial-gradient(58% 58% at 50% 52%, var(--cover-color-soft), transparent 72%);
  filter: blur(64px);
  opacity: 0.42;                    /* 播放时 0.55 / 暂停 0.28 */
  transition: opacity 600ms var(--ease-in-out-screen);
}
```

**只有一层材料。** Apple §12：**"Never stack a light translucent surface on another"**。

### 6.3 时长（北欧的耐心 vs Apple 的响应）

| 类型 | 时长 | 谁定 |
|---|---|---|
| 手势驱动 | **180–260ms** | Apple（要跟手） |
| 状态切换 | **200ms** | Apple（反馈要即时） |
| C2 几何形变 | **380–420ms** | 北欧（几何变化需要时间看清） |
| 氛围光 | **600ms** | 北欧（环境变化应该慢） |

> **这个双轨不是随意值**：**有手指在屏幕上 → Apple 的快；界面自己在说话 → 北欧的慢。**

## 7. 颜色：降为最末（这是系统设计的必然结果）

**当前三份方案里，颜色都是最早决定的。这是错的——颜色在系统里是最后一步。**

因为：**如果状态已经由 C1（光）与 C2（形）唯一确定，颜色就只剩"强调"和"语义"两个功能。**

```css
:root {
  /* ── 基底：只分三层（C1/C2 都在其上） ── */
  --bg-void: #000000;        /* Nothing 的真黑：状态灯要在真黑上才准 */
  --bg-far:  #0A0A0B;
  --bg-mid:  #111112;

  /* ── 文字：三级（C3 用） ── */
  --text-primary:   #FFFFFF;   /* 21:1 */
  --text-secondary: #B0B0B4;   /* 9.6:1 */
  --text-muted:     #757579;   /* 4.7:1 —— C2 的标注用，达标 */

  /* ── 语义：C1/C2 只用这三个 ── */
  --signal-ok:     #FFFFFF;    /* 正常态不着色（Nothing：不必要时不用色） */
  --signal-warn:   #C9A227;    /* 降级：琥珀，慢闪 */
  --signal-error:  #D71921;    /* 真失败：红，急闪。**仅此一处用红** */

  /* ── 唯一的功能性强调色 ── */
  --accent: #D71921;           /* 当前项 / 激活节点。**不跟封面** */

  /* ── 材质 ── */
  --cover-color-soft: rgb(110 110 120 / 0.5);   /* 只驱动氛围光 */
}
```

**红色的约束（系统级）**：
> 红色**只用于 `ERR_*` / `fatal` / 协议错误**。
> **降级不用红**（用琥珀虚线）——因为你的机器**长期处于降级状态**，红色会失去信号价值。

## 8. 通道降级（R3：预设计，不是补丁）

| 条件 | C1 | C2 | C3 |
|---|---|---|---|
| `prefers-reduced-motion` | 呼吸→**恒定亮度**；扫描→**离散步进**（每 500ms 跳一格） | 形变→**瞬时切换**（不插值） | **不变**（承载语义） |
| `prefers-contrast: more` | 提高对比，保留全部模式 | 加描边，线宽 +0.5px | **不变** |
| 色盲 (deuteranopia) | 琥珀/红**同时用闪频区分**（慢/急） | **不变**（几何本身无色彩依赖） | 加文字标注 |
| 窗口过窄 (<900px) | **不变** | 路径**压缩为 3 段**（合并解码+源率） | 文字截断 |
| 深色/浅色 | 呼吸/扫描逻辑不变 | **不变**（几何与色彩无关） | **不变** |

> **关键性质**：C2 的编码**完全不依赖颜色**（点/格/线/角度/虚实），所以**色盲与浅色主题下零损失**。
> 这是"几何即语义"带来的免费收益——**如果用颜色编码音质，这两个场景都要重做。**

## 9. 落地顺序

| # | 步骤 | 成本 | 为什么排这里 |
|---|---|---|---|
| **1** | 实现 **C2 的静态语法**（信号路径四段 + 折线/虚线/实心空心） | 中 | **系统的心脏**，且数据全部现成 |
| **2** | 实现 **C1 的四模式**（全暗/常亮/呼吸/扫描） | 小 | 覆盖全部播放状态 |

| **5** | 进度条 Apple 化（§5.3） | 中 | 交互体验 |
| **6** | 氛围光（北欧） | 小 | 最后加 |
| **7** | 颜色令牌替换（§7） | 小 | **颜色最后做**——它已经是配角 |

> **做到第 3 步，系统就已经成立**；第 4–7 步是把它做漂亮。
