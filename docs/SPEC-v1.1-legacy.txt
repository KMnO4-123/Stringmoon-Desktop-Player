第 0 章  重要事实更新（2025-10 许可证变化）
================================================================================

以下 5 项事实直接影响 v1.0 的技术选型与法律可行性，属于"必须知道"：

0.1 VST3 SDK 已转为 MIT 许可（2025-10-20，SDK 3.8 起）
- 无需任何签约、费用或注册即可在闭源宿主中集成 VST3。
- 旧有的 GPLv3 / 专有双许可模式已不再提供（以官方开发者门户为准）。
- 影响：v1.0 中"VST3 宿主"功能的法务前置工作可以全部删除，
  原本最大的许可证风险项之一消除。仅需保留版权声明。
- 注意：VST2 不在授权范围内，不要顺手做 VST2 兼容。

0.2 ASIO SDK 改为双许可（2025-10-15，SDK 2.3.4 起）
- 可选：GPLv3（整体开源）或 Steinberg 专有许可（保留既有条款）。
- 影响：本项目若闭源发布，走"专有许可"路径即可（条款不变，免费获取）；
  若走 GPLv3 路径则整个应用必须开源。建议：闭源发布 → 专有许可；
  同时遵守 ASIO 商标使用规范（如展示 "ASIO Compatible" 标识）。

0.3 Slint 三许可确认：GPLv3 / 免版税许可 / 商业许可
- 免版税许可（Royalty-Free）：专有（闭源）桌面应用可免费使用，
  唯一义务是在"关于"对话框等处注明使用了 Slint（可使用官方 AboutSlint 组件）。
- 也就是说：闭源桌面应用无需购买商业许可，只需保留署名。
  （嵌入式系统除外——本项目是桌面应用，不受此限。）
- 辅助功能：Slint 自 1.1 起内置 AccessKit 集成，桌面平台屏幕阅读器支持
  开箱即用；国际化采用 gettext（@tr() 宏）。
- 当前稳定版为 1.18.x（2025-09）。建议锁定 1.x 最新稳定版。

0.4 MQA 现状：建议本方案放弃 MQA 渲染
- MQA Ltd 已进入破产管理，资产由 Lenbrook（Bluesound/NAD 母公司）收购，
  重组为 MQA Labs；原 MQA 解码/渲染授权体系复杂，新集成需与 Lenbrook 谈判。
- 主流平台（TIDAL 等）已转向 FLAC。
- 技术结论：MQA 文件在没有解码器时仍可作为普通 44.1/48kHz PCM 正常播放。
  建议：v1.0"可选 MQA 解码模块"降级为"按基础层 PCM 播放，不做渲染"，
  从路线图删掉相关工时，避免法务与工期双重成本。

0.5 librespot 仍活跃且为 MIT（v0.8.0，2025-11）
- 可作为 Spotify Connect 接收端（仅 Premium 账号）。
- 代码 MIT，但注意：连接 Spotify 服务属其服务条款范畴，MIT 只解决代码授权，
  不解决服务授权；闭源产品集成前需自行评估 ToS 风险（见第 8 章）。

第 1 章  总体评估：v1.0 亮点与 12 项缺口
================================================================================

亮点（保留）：
- "C++20 引擎为唯一音频权威 + 瘦 UI + 类型安全桥接"的三层结构正确且专业；
- SPSC 无锁、快照式状态同步、音频数据不穿越桥接层——这些原则都符合
  成熟音频软件的做法，方向完全正确；
- 设计语言（澄明之境）自洽，动效有物理依据的约束（"绝不用线性曲线"）难得；
- 刻意不做清单（社交/商店/下载器）体现了克制，值得坚持。

缺口（本稿逐项补全）：
G01  许可证与合规：全篇未提任何组件的许可证（FFmpeg/Slint/SoX/VST3/ASIO/
     TagLib/Chromaprint 等），直接影响能否闭源发布与分发方式；已补（第 8 章）。
G02  内存预算内部矛盾：2.2 节称 Slint 占 50–80MB，而 2.7/五章目标"空闲 ≤40MB"
     不可能同时成立；需重定预算（第 5/11 章）。
G03  延迟指标乐观：WASAPI 独占"端到端 ≤6ms"未计入 DAC/USB 传输；需修正口径。
G04  DSD 章节过于简略：未提 DoP 封装参数、Native DSD 在 WASAPI 的可行条件、
     以及"DSD 域无法做数字音量/ EQ"这一关键冲突；已补（3.7）。
G05  进程模型含糊："独立服务进程/线程"二选一未决策；已给出结论（第 4 章）。
G06  VST3 宿主缺架构细节：进程隔离、扫描、崩溃隔离、GUI 嵌入方式；已补（3.8）。
G07  UI 工程不可施工：湿玻璃/模糊/透明窗口/自定义光标在 Slint 中的支持度
     未验证，多条动效需降级方案；已给能力核对表（5.1）。
G08  曲库层缺数据设计：无 Schema、无扫描管线、无搜索方案、无迁移策略（第 6 章）。
G09  完全缺失工程化：测试策略、CI、打包、自动更新、代码签名、崩溃报告、
     日志与隐私开关（第 7 章）。
G10  无障碍 / i18n / 高 DPI / 动效降级（reduced motion）未提及（5.2–5.5）。
G11  平台接入法律风险未标注：网易云/QQ"API 代理"路径存在明确 ToS/法律风险，
     需改为风险隔离设计（第 8 章）。
G12  路线图过于乐观且重复出现（2.8 与六章重复）：约 8–10 周覆盖全部范围
     不现实；已重写为"阶段 0 验证 + MVP + 门禁"结构（第 10 章）。

第 2 章  可用补充资源总清单（现成轮子，直接可用）
================================================================================
说明：★ = 强烈建议引入；○ = 建议评估后引入；△ = 仅备选。
许可证为本稿写作时核实结果，引入前请再次确认（尤其 LGPL 的链接方式）。

【解码 / 格式】
★ FFmpeg（LGPL-2.1+，注意构建配置）—— 主力解码后端。
  关键：必须使用 --disable-gpl 的 LGPL 构建，避免 HEVC 等 GPL 组件污染；
  动态链接 so 文件需满足 LGPL"可替换库"要求（提供 DLL 与文档）。
  MP3/AAC/FLAC/ALAC/WavPack/Vorbis 解码器均在 LGPL 集合内。
★ WavPack 官方库（BSD-3）—— WavPack 解码首选，无需走 FFmpeg。
★ dr_libs（单头文件，MIT/公有领域）—— wav/flac/mp3 轻量解码，
  适合启动路径、预览、测试向量生成，减少对 FFmpeg 的依赖面。
○ libsndfile（LGPL-2.1）—— WAV/AIFF/CAF 等 PCM 容器读写；
  如仅播放可省，但批量导出/转换有用。
○ TagLib（LGPL-2.1 / MPL-2.0 双许可）—— 元数据读写事实标准；
  选 MPL-2.0 路径对闭源更友好。中文 ID3 编码兼容性好。
△ Monkey's Audio / Musepack 等小众格式：社区库许可证杂乱，默认不支持。

【音频输出 / 设备】
★ WASAPI（系统 API）+ IAudioClient3 —— 共享模式最小周期查询

第 3 章  引擎层深度补充
================================================================================

3.1 线程与优先级（MMCSS）
--------------------------------------------------------------------------------
- 渲染线程注册 MMCSS：AvSetMmThreadCharacteristicsW(L"Pro Audio", &taskIndex)，
  退出时 AvRevertMmThreadCharacteristics。注册后由系统保证调度配额。
- 线程优先级：渲染线程 THREAD_PRIORITY_TIME_CRITICAL（独占模式）或
  HIGHEST（共享模式）；解码/IO 线程 BELOW_NORMAL；扫描线程 IDLE。
- 若 MMCSS 注册失败（返回 0），不要提升到 TIME_CRITICAL 硬扛——降级为
  HIGHEST 并记录诊断日志（避免饿死系统线程导致整机卡顿）。
- 命令队列处理点在"每个音频块边界"，且一次最多处理 N 条（如 32 条）
  防止 UI 洪泛命令导致单块超时——剩余命令留到下一块。
- SPSC 环形缓冲区：alignas(64) 防伪共享；索引使用
  std::atomic<size_t> 且仅用 acquire/release，不用 seq_cst 拖慢热路径。

3.2 延迟指标修正（口径重定义）
--------------------------------------------------------------------------------
v1.0："WASAPI 独占 ≤ 6ms"表述含糊。修正为两个口径：
- 应用侧延迟（引擎提交到驱动缓冲）= 周期 × 缓冲数，例：3ms × 2 = 6ms；
- 端到端可感延迟（含 USB/驱动/DAC 链路）≈ 8–14ms（USB DAC 典型值），
  板载声卡更低、蓝牙明显更高（100–300ms，且独占模式不可用）。
建议：指标表改用"应用侧 ≤6ms / 端到端实测 8–14ms（设备相关）"，
并在 POC 中用回环实测校准（7.1）。避免宣传口径翻车。

3.3 欠载 / 设备热插拔 / 恢复策略（v1.0 缺失）
--------------------------------------------------------------------------------
- 欠载（xrun）处理：音频回调内不做任何日志/分配；回调外线程读取
  原子计数，记录时间戳/缓冲余量，写环形诊断日志。
- 自适应扩容：连续 3 次欠载 → 缓冲 ×2（上限 50ms）→ 提示
  "已提升播放稳定性（缓冲 3ms → 6ms）"；24 小时无欠载且有
  "激进低延迟"选项时才回缩。
- 设备热插拔：注册 IMMNotificationClient，监听默认设备变化/移除；
  收到 AUDCLNT_E_DEVICE_INVALIDATED 后：淡出 10ms → 释放流 →
  按设备 ID 重试重开 → 失败回退默认设备 → 淡入 20ms。
  蓝牙设备：自动降级共享模式（独占不可用）并加大缓冲。
- 设备切换期间的 UI 反馈沿用 v1.0 设计（音量图标变形为设备图标）。
- 独占模式被其他应用占用（Teams/Zoom 等）：检测 Initialize 失败 →
  静默降级共享模式，在"音频设置"中留下一条可读原因，不弹窗打断。

3.4 采样率与位深策略（含抖动，v1.0 缺失）
--------------------------------------------------------------------------------
- 内部处理格式：统一 float32（DSP 图精度足够；重采样中间态可用 double）。
- 链路：解码源格式 → float32（无损整数→浮点转换）→ DSP → 设备格式转换。
- 采样率策略：
  · 独占模式：按源采样率重开流（bit-perfect 直达），曲目切换时
    10–20ms 淡出/淡入覆盖重建间隙；
  · 共享模式：不重开流（避免系统混音器抖动），源≠设备率时启用 SoXR；
  · 同一采样率时 SoXR 完全不激活（v1.0 已写了，强调落实为断言）。
- 位深抖动：输出位深 < 源位深（如 32f → 16bit）时启用 TPDF dither；
  16bit 输出推荐 TPDF（±0.5 LSB 满幅）；如需可选项提供噪声整形。
  bit-perfect 模式（独占 + 无音量衰减 + 无 DSP）下禁用抖动，直通。
- 音量：软件音量在 float 域，10ms 时间常数一阶平滑防 zipper noise；
  bit-perfect 模式时音量滑块提示"将退出 bit-perfect"。

3.5 EQ 施工参数（把"10 段 IIR 双二阶"落到数字）
--------------------------------------------------------------------------------
- 频率点（1 倍频程）：31.25 / 62.5 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k Hz
- 滤波器：RBJ cookbook peaking EQ（双二阶），默认 Q=1.41，可调 0.5–4；
- 增益范围 ±12dB，步进 0.5dB；频响目标：平直时 THD+N 不可测劣化。
- 参数平滑：每个滤波器系数向目标值做每样本指数插值（≈20ms），
  避免拖动滑块时产生爆音/zipper。
- 削波保护：自动前级（preamp = -max(0, 最大正增益)）默认开，
  或可选 2ms lookahead 软限幅器；两者二选一，不要叠加。
- 旁路：EQ 开关做 30ms 交叉淡变，避免瞬态咔哒。

3.6 ReplayGain 2.0 细则
--------------------------------------------------------------------------------
- 扫描：libebur128，整轨 + 专辑（album gain 需同专辑批量）；
  写库（tracks.rg_*）+ 可选写回标签（写回前备份策略：先写临时文件再替换）。
- 播放：目标响度默认 -18 LUFS（RG2 惯例），提供 -23 / -16 / -14 选项；
  Gain 应用前检查 rg_track_peak：peak×gain > -0.1dBFS 时按
  "防削波"模式自动再衰减至 -0.1dBFS。
- 模式：关闭 / 单曲 / 专辑（默认单曲）；切换即时生效（30ms 平滑）。
- v1.0 的"动态层实时 RMS 压缩"其实是一台简易限幅器——单独做开关、
  默认关闭，不要和 ReplayGain 混在一个"音量均衡"概念里（会互相干扰）。

3.7 DSD 专章（v1.0 只写了两行，这里补齐可施工细节）
--------------------------------------------------------------------------------
① 播放路径一：DoP（DSD over PCM，走 WASAPI 独占）
- 封装：DSD64 → 24bit/176.4kHz PCM；DSD128 → 352.8kHz；DSD256 → 705.6kHz
  （设备需支持该 PCM 率）；每 24bit 帧装 16bit DSD（2 通道交错）+ 8bit 标记，
  标记 0x05/0xFA 交替。
- 铁律：DoP 路径禁止一切 DSP——EQ、重采样、变速、数字音量全部旁路，
  否则标记被破坏、DAC 无法识别。
- DoP 播放时音量控制：数字音量不可用；可选 A) 界面音量直通（由 DAC/功放控制）
  并明确提示；B) 转 PCM 路径（见③）。

② 播放路径二：Native DSD
- Windows 上 Native DSD 实际依赖 ASIO 驱动（Thesycon 系等）暴露 DSD 率，
  WASAPI 一般不以原生格式暴露 DSD——v1.0 未说明此前提，补充：Native DSD
  仅在 ASIO 后端下提供；不可用时自动降级 DoP 或 PCM 并提示。

③ DSD → PCM（当用户开启 DSP 时）
- FIR 半带抽取滤波（参考 dsd2pcm 算法思想自研，勿链接 GPL 代码）；
  DSD64→176.4kHz 起步，再进入常规 DSP 链。
- 规则：一旦检测到 EQ/重采样/变速/衰减音量被激活 → 自动切换转 PCM 路径，
  播放栏出现 "DSD → PCM（已转换）" 小徽标，可一键切回直通。

④ PCM → DSD（调制输出，v1.0 的"PCM→DSD 调制"）
- 需噪声整形 ΣΔ 调制器（建议级联 2 阶 × 3 或 6 阶），实现难度与
  风险都高；建议排在最后（Could 级），先完成①②③。
- 校验方法：调制输出经 dsd2pcm 逆转换后与源对比，要求带内 THD+N
  优于 -100dB 量级（按目标 DSM 率放宽）。

3.8 VST3 宿主架构（配合 0.1 的 MIT 许可，此功能风险大降）
--------------------------------------------------------------------------------
- 分阶段策略（避免首版就吞下最难的沙箱）：
  v1（MVP 后）：进程内加载 + 崩溃防护——结构化异常捕获
    （SetUnhandledExceptionFilter/AddVectoredExceptionHandler），
    插件崩溃即标记黑名单 + 自动旁路 + 提示；扫描器独立进程；
  v2（稳定后）：进程外宿主（sandbox），共享内存传输音频块、
    IPC 传参数，插件 GUI 跨进程嵌入为独立窗口（复杂度高，谨慎排期）。
- 扫描：独立进程扫描（.vst3 目录），异常退出=坏插件，写黑名单；
  首次扫描需用户确认目录。
- 参数：采样点级自动化参数平滑（20ms 斜坡）；托管延迟
  （latency samples）需向引擎上报并纳入延迟补偿计算。
- RT 约束：插件 process() 在渲染线程内联执行——进程内模式下，
  一个劣质插件可以直接打死音频线程，这正是 v2 沙箱的意义；
  v1 即需认真做黑名单与异常恢复。
- VST3 SDK 的 hosting 示例（editorhost/validator）作为起点。

3.9 无缝播放与交叉淡入淡出实现要点
--------------------------------------------------------------------------------
- 预解码：始终保持下一首 ≥1 首完整体在解码缓冲（本地 ≥2s 前导，
  网络流 ≥8s）；同专辑曲目间用采样级拼接（gapless）。
- 判定"同专辑"：album + album_artist + 连续 track_no + 无用户强制切歌。
- 交叉曲线：等功率曲线（equal-power, sin/cos 交叉），v1.0 的
  150/300/500ms 时长保留；交叉在设备采样率域执行，异采样率曲目
  先各自重采样对齐。
- "尾部渐弱/硬切"检测：尾部 2s 窗口 RMS 斜率分析（斜率 < -6dB/s
  判为渐弱 → 交叉缩短至 150ms；>3dB/s 突降判为硬切 → 交叉延长至 500ms）。
- 手动切歌不交叉、立即切换（v1.0 已定），补充：切歌做 5ms 淡出防爆音。

3.10 内部数据流格式定义（建议写入引擎头文件）
--------------------------------------------------------------------------------
decode → float32 interleaved? 否——DSP 图内部用 deinterleaved(planar)
       → DSP 链（EQ/重采样/变速...）→ interleaved 输出转换（含 dither）
       → WASAPI/ASIO 缓冲。
理由：planar 对双二阶/重采样实现更友好；仅在输出边界做一次交织。
所有环缓冲元素为 float32；命令结构体固定 64 字节对齐、POD、无指针。

第 4 章  桥接层深度补充
================================================================================

4.1 进程模型决策（回答 v1.0 的"独立服务进程/线程"含糊处）
--------------------------------------------------------------------------------
结论：主引擎与 UI 同进程（多线程）；仅 VST3 插件宿主（v2）与插件扫描器
使用独立进程。理由：
- 跨进程音频共享内存会引入额外抖动与复杂度，个人播放器场景收益为负；
- 内存预算紧张（见 5.4），双进程模型每个进程的基线开销不可接受；
- UI 崩溃=应用崩溃的风险在本场景可接受（音乐播放器非常驻服务），
  用崩溃报告兜底。
术语修正：同进程下不存在"IPC"——桥接层是 C ABI + 环形缓冲 + 快照，
"IPC/共享内存"术语仅用于插件进程与平台适配 sidecar。

4.2 接口契约强化（v1.0 示例仅有函数原型，补充工程规范）
--------------------------------------------------------------------------------
- 版本与尺寸：engine_create 接收 struct EngineConfig{ size_t struct_size;
  uint32_t abi_version; ... }；ABI 版本不匹配时拒绝创建并返回明确错误码。
- 错误码：enum EngineStatus { OK, ERR_DEVICE, ERR_DECODE, ERR_BUSY,
  ERR_INVALID_ARG, ERR_VERSION ... }，跨 C 边界绝不抛异常。
- 线程约定：每个函数注释标明可调用线程（UI 线程 / 任意线程 / 仅控制线程）。
- 回调约定：引擎→UI 的事件回调不得在渲染线程上调用（经控制线程
  转发队列）；回调内禁止阻塞。
- 字符串：全 UTF-8，明确长度上限与截断规则。

4.3 快照同步的实现细节
--------------------------------------------------------------------------------
- 快照结构（播放位置/状态/队列摘要）用三缓冲（triple buffer）或
  seqlock：写者（控制线程）无锁写，读者（UI 帧循环）无锁读，
  保证读到完整一致快照，无需锁也无需双份分配。
- 100ms 推送保留；但 UI 帧循环自取（pull）比事件推送（push）更稳——
  建议 pull 模式：UI 每帧读最新快照，引擎只更新快照不推事件。
- 频谱数据：引擎可选 FFT 节点（256/512 点，30fps 节流）写入共享
  ring；UI 侧无消费者时节点不计算（零开销原则的落实方式）。

5.4 性能预算修正（消除 v1.0 内部矛盾）
--------------------------------------------------------------------------------
基于组件基线（Slint 桌面应用实测普遍 50–80MB；引擎 10–20MB）：
- 空闲（启动、无播放）：内存 ≤ 90MB、CPU < 0.5%
- 播放中（独占、无 DSP、列表浏览）：内存 ≤ 100MB、CPU < 1%
- 播放中（EQ+重采样）：CPU < 3%
- 最坏叠加（全部视觉 + DSP）：CPU < 8%、内存增量 ≤ 40MB
- 迷你模式：内存 ≤ 80MB、CPU < 1%
若必须坚持 v1.0 的 ≤60MB，唯一路径是软件渲染 + 削减视觉效果——
列为阶段 0 的显式 Go/No-Go 决策（用实测数据选路），不要两头都要。

5.5 其余 UI 规范补充
--------------------------------------------------------------------------------
- 高 DPI：Per-Monitor DPI Awareness V2；所有 0.5px 线在非整数缩放
  （125%/150%）下用物理 1 像素替代，避免灰糊。
- 亮色变体：以"晨雾"为名的浅色主题（雾白底 #F4F5F7 + 冷灰层），
  复用同一套材质公式（光从上方、湿玻璃规则不变，仅还原色不同）；
  结构上主题即一组颜色令牌，不做两套布局。
- 睡眠场景：不要用纯黑（0,0,0）+ 全灭——保留 2% 亮度的星空底纹，
  避免 OLED 残影与"死机感"。
- 动效降级表：为每条形如"封面倾斜/光晕指针/浸入歌词"的动效定义
  低配档（无 GPU 加速 or reduced-motion 时）与关闭开关（一个总开关 +
  分组开关）。v1.0 的"任何视觉效果不运行时零 CPU"原则保留并写成断言。

7.1 测试策略
--------------------------------------------------------------------------------
- 单元（Catch2/doctest）：
  · DSP 黄金测试：标准 WAV 输入 → EQ/重采样/增益 → 与参考输出对比
    （频响 ±0.1dB、THD+N 阈值）；  测试向量含 44.1/96/192kHz、单双声道；
  · RG 扫描数值与参考实现（loudgain）对齐 ±0.05dB；
  · 容器/标签解析（LRC/CUE/M3U/内嵌封面）含中文与损坏样本。
- 实时安全：Clang RTSan（-fsanitize=realtime + [[clang::nonblocking]]）
  纳入 CI——渲染回调路径出现 malloc/锁/系统调用即红；另加 TSan（桥接/
  线程、仅 debug）、ASan/UBSan（debug）。这是 v1.0"无锁无分配"
  约束从文档变成可执行保证的关键。
- 集成：30 分钟独占最小缓冲压力播放 = 0 xrun 断言；设备矩阵：
  板载/USB DAC/蓝牙 × 44.1–384kHz × DSD64–256（设备支持范围内）。
- 延迟测量（自研小工具）：输出 chirp，WASAPI loopback 捕获，
  互相关求延迟；CI 环境可跳过，发布前手动跑并记录。
- UI：Slint testing backend 做可访问性树断言 + 关键页面快照；
  动效帧时间采集（p95 < 16.7ms 断言，仅开发机构建）。
- 模糊测试：LRC/CUE/M3U/标签二进制解析器用 libFuzzer 跑整夜。

7.2 CI/CD
--------------------------------------------------------------------------------
- 主编译器 MSVC（cl）；辅助 clang-cl（用于 RTSan 构建）；
  CMake Presets + vcpkg manifest（锁版本、可复现构建）；
  clang-format 强制 + clang-tidy（performance/readability/cert 子集）。
- 流水线：构建 → 单测 → RTSan 作业 → 打包（portable zip + Inno Setup）
  → signtool 签名（含时间戳）→ 生成 appcast.xml → 发布候选。
- 发布节奏：两阶段 appcast（先内部通道 key，再全量切换），
  替代 WinSparkle 不支持的灰度。

7.3 打包 / 更新 / 安装
--------------------------------------------------------------------------------
- 安装形态：安装版（Inno Setup，per-user 免管理员；文件关联写
  HKCU；卸载默认保留曲库/设置并询问）+ 便携版（--portable 或
  portable.ini 开关，数据写程序目录）。MSIX 列为后续选项。
- 自动更新：WinSparkle（MIT）——appcast + 内建签名校验；
  更新包签名密钥离线保管；更新前自动备份 DB。
- 关闭行为：默认"最小化到托盘"，设置中可选"直接退出"；
  托盘菜单：播放控制 + 退出（Win32 Shell_NotifyIcon 自实现）。
- 首次启动向导：选择音频后端（独占/共享/自动）、添加音乐文件夹、
  平台桥接开关（默认关）——三步内完成。

7.4 崩溃报告与日志
--------------------------------------------------------------------------------
- Crashpad 或 sentry-native；本地 dump 保留 + 可选上传（默认关，上传前
  展示将发送的内容摘要）。符号文件在 CI 归档并上传符号服务器。
- 日志：环形缓冲 + 异步写文件（超过 2MB 滚动，保留 3 份）；
  音频诊断段（xrun 计数、缓冲史、设备变更史）单独文件，便于用户反馈。
- 隐私：默认零遥测；网络请求清单在设置中可查（"网络活动"页）；
  全局"离线模式"开关一键切断所有网络功能。

7.5 安全清单
--------------------------------------------------------------------------------
- 本地 HTTP API / API 代理：仅绑定 127.0.0.1；每会话随机 token
  （请求头校验）；关闭 CORS（默认不响应跨源）；写操作二次确认。
- 凭证：Windows DPAPI（CryptProtectData，用户级）加密存储；
  OAuth 走 PKCE + loopback，回调端口随机。
- 更新通道：HTTPS + 签名校验缺一不可。
- 插件扫描：用户确认目录、独立进程、黑名单持久化。
- 解析器边界：M3U/CUE/LRC 全部输入按不可信数据处理（长度/嵌套上限）。

- 网易云 / QQ 音乐等"本地代理处理签名与 Cookie"的第三方 API 方案：
  未经授权访问其接口通常违反平台服务条款，且涉及（至少）灰色地带；

- 建议设计（风险隔离，而非鼓励绕过）：
  · 不内置任何未授权解析逻辑；相关能力只以"社区插件"形式存在，
    由用户自行安装、自行承担合规责任，主安装包不含相关代码；
  · 产品层面优先支持合法路径：自托管（Navidrome/Jellyfin →
    OpenSubsonic 协议）、本地文件、官方开放能力；
  · 文档明确声明"不提供音乐内容、不绕过任何付费机制"。
- Spotify（librespot）：代码 MIT，但服务接入属 ToS 范畴；
  同样建议后置为可选插件并保留免责声明。

10.1 阶段 0：技术验证（1–2 周，Go/No-Go 决策点）
--------------------------------------------------------------------------------
按优先级执行 8 项 spike（每项 0.5–2 天），产出《技术验证报告》：
S1 Slint × C++20 引擎最小集成：播放一个 WAV；测内存基线（校准预算）
S2 WASAPI 独占 3ms 周期：30 分钟压力播放，统计 xrun
S3 环形缓冲 + 命令队列原型：RTSan 通过（零违规）
S4 Slint 效果盘点 POC：径向渐变/发丝线/透明窗口/光标隐藏/IME
S5 SQLite 10k 曲库 + 虚拟列表：首屏与滚动帧率
S6 DoP 链路验证（若有 DSD DAC；无设备则用回环波形验证封装）
S7 VST3 SDK（MIT）加载与直通 POC
S8 TagLib 中文样本 + CUE/LRC 解析验证
决策：内存预算定稿（90MB 路线 vs 60MB 软渲染路线）、效果降级清单定稿。

10.2 主线路线（修订版）
--------------------------------------------------------------------------------
阶段 1 · MVP 播放内核（6–8 周）
  引擎（WASAPI 独占/共享、解码、Gapless、命令/快照模型）
  + Slint 基础 UI（三区布局、列表、播放栏）
  + SQLite 曲库（扫描/搜索/封面）
  验收：10k 曲库流畅；独占 0 xrun（30min）；内存符合定稿预算；
        启动到发声 < 1s。
阶段 2 · 体验完善（4–6 周）
  歌词（LRC/浸入动效）、快捷键、SMTC、托盘、智能续听、
  睡眠定时器、迷你模式、拖放与文件关联
  验收：动效 60fps（p95 < 16.7ms）；系统媒体面板同步正确。
阶段 3 · 专业音频（4–6 周）
  ASIO、EQ、ReplayGain、SoXR、DSD（DoP + 转 PCM 路径）、
  设备热插拔全链路
  验收：EQ/重采样黄金测试通过；DSD 直通/转换切换无爆音；
        延迟实测记录进报告。
阶段 4 · 工程化收口（2–3 周）
  打包安装/便携、WinSparkle 更新、代码签名、崩溃报告、
  无障碍完善、i18n（zh/en）
  验收：从旧版可自动更新成功；全链路签名通过 SmartScreen 检查。
阶段 5 · 扩展（持续，按 MoSCoW）
  Subsonic/OpenSubsonic Provider → 智能去重 → 音乐地图 →
  VST3 宿主 → PCM→DSD 调制 → 其他 Provider。

10.3 MoSCoW 砍功能清单（对抗范围蔓延）
--------------------------------------------------------------------------------
Must   ：播放/曲库/歌词/WASAPI/EQ/RG/快捷键/SMTC/打包更新
Should ：ASIO、静音去重、音乐地图、迷你模式、睡眠定时器、场景模式
Could  ：VST3、DSD 调制输出、平台桥接、聆听房间、智能播放列表
Won't  ：社交、商店、内置下载器、MQA 渲染、3D/粒子特效、AI 黑盒调音

10.4 时间现实性说明
--------------------------------------------------------------------------------
v1.0 的"2-3 + 3-4 + 2-3 周"接近全程 2 个月——对单人全职、且需要
自研引擎的规模而言过于乐观。现实估算：
- 到可用 MVP（阶段 0–1）：约 2–3 个月；
- 到"体面 v1.0"（含阶段 2–4）：约 6–9 个月；
- 全部范围（含阶段 5）：12 个月+。
建议以阶段门禁管理：每阶段结束用验收标准决定继续/砍功能/延期，
而不是死守一张总甘特图。若为多人团队（引擎 1 + UI 1 + 数据 1），
可压缩约 40%，但桥接接口需先冻结。

附录 A  关键常量速查
================================================================================
- 独占缓冲：起步 3ms × 2 周期；欠载自适应 ×2，上限 50ms
- 共享模式：查询设备最小周期，起步 min×2；蓝牙自动 ≥20ms
- 预解码：本地 ≥2s 前导；网络流 ≥8s；交叉淡入淡出 150/300/500ms
- 快照周期：100ms（pull 模式）；频谱节流 30fps
- EQ：10 段 31.25–16k Hz（1 倍频程）；RBJ peaking；Q 默认 1.41；
      ±12dB/0.5dB 步进；系数平滑 ≈20ms
- ReplayGain：RG2 / 目标 -18 LUFS（备选 -23/-16/-14）；防削波 -0.1dBFS
- Dither：输出位深 < 源位深时 TPDF；bit-perfect 路径禁用
- DoP：DSD64→176.4k / DSD128→352.8k / DSD256→705.6k；24bit 容器；
      标记 0x05/0xFA；DSD64 每帧 16bit DSD/通道
- 文件监控去抖：2s；扫描批事务 200 条；日志滚动 2MB×3
- 音量平滑：一阶 ≈10ms；EQ 旁路交叉 30ms；切歌淡出 5ms
- 封面缓存尺寸：40 / 56 / 96 / 300 / 600 px（SHA1 命名）
