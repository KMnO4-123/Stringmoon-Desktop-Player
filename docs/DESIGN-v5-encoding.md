## 1. Nothing 的系统设计内核（来自 GDK，不是审美描述）

### 1.1 关键事实：Glyph **不是几盏灯，是一个定长可寻址数组**

GDK 用**逐型号的索引表**定义它：

| 机型 | 通道 | 索引 |
|---|---|---|
| Phone (1) | `A1` / `B1` / `C1-C4` / `D1_1-D1_8` / `E1` | 0 / 1 / 2-5 / 7-14 / 6 |
| Phone (2) | 加上 `A2`、`C1_1-C1_16`、`C2-C6` | 0-32 |
| Phone (2a) | `A` / `B` / `C1-C24` | 25 / 24 / 0-23 |
| Phone (3a) | `A1-A11` / `B1-B5` / `C1-C20` | 20-30 / 31-35 / 0-19 |
| Phone (4a) | `A1-A6` | 0-5 |

**每台设备的数组长度、顺序、方向都不同**（"D1_1 is the bottom"，"C1_1 is bottom right"）。

> **这条教会我们的不是"要有灯"，而是**：
> **编码方案的载体是一个受限的、有明确容量的、可寻址的空间。**
> 设计师必须先接受这个容量上限，再在里面想办法——**而不是先想效果，再要求硬件配合**。

### 1.2 关键事实：编码只有 **4 个维度**

`GlyphFrame` 的参数是**全部**（GDK 就这四个）：

| 维度 | API | 语义 |
|---|---|---|
| `channel[]` | `buildChannel(...)` | **哪些**（**空间/位置**） |
| `period` | `buildPeriod(ms)` | **亮多久**（**时长**） |
| `cycles` | `buildCycles(n)` | **重复几次**（**计数**） |
| `interval` | `buildInterval(ms)` | **间隔多长**（**节奏**） |

**没有颜色、没有亮度值、没有渐变。**

> **这就是"受限通道"的全部含义**：四个维度，表达一切。

### 1.3 关键事实：输出操作只有 **5 个**

| 操作 | 语义 | 我方案里的对应 |
|---|---|---|
| `toggle(frame)` | **常亮/常灭** | C1「常亮」 |
| `animate(frame)` | **呼吸动画**（GDK 原文就叫 breathing） | C1「呼吸」 |
| `displayProgress(frame, p)` | **进度**（仅 C1/D1 通道） | C2 的**填充** |
| `displayProgressAndToggle(frame, p, reverse)` | 进度 + 其余全亮 | C2 + C1 组合 |
| `turnOff()` | 全灭 | C1「全暗」 |

> **我的 v3/v4 凭空想的"四种模式：全暗/常亮/呼吸/扫描"——其中三个直接对应 GDK 的真实操作**（`turnOff`/`toggle`/`animate`）。
> **第四个"扫描"应改为 GDK 的 `displayProgress`**（进度填充），因为它**带真实进度值**，比扫描动画信息量更大、且不依赖动画（reduced-motion 友好）。

### 1.4 关键事实：**约束决定设计**（这条最值得学）

GDK 明确写着：

> `displayProgress(frame, progress)` — Used to display a progress value on **C1 / D1**. **Limited to D1 only for Phone (1).**

**硬件的通道限制，直接决定了设计的边界**——Phone (1) 只能在 D1 上做进度，那就接受它。

**同理，生命周期的约束也是显式的**：

```
init() → register() → openSession() → [使用] → closeSession() → unInit()
```

**会话必须显式开关、必须释放**。Nothing 没有假装这是无成本的。

> **翻译到我们的项目**：C1 的载体（屏幕区域）和 C2 的画布（播放栏空间）都有**真实容量上限**——比如播放栏只有 72px、顶栏只有 48px。
> **必须先承认这些上限，再设计编码**，而不是先画效果图再削足适履。

### 1.5 提取出的系统设计原则（四条）

| # | 原则 | Nothing 的体现 |
|---|---|---|
| **P1** | **载体是先验约束** | 逐型号的通道表；硬件定死容量 |
| **P2** | **维度和操作都极少** | 4 个维度、5 个操作，然后穷尽组合 |
| **P3** | **编码靠几何/时序，不靠颜色与亮度** | 没有颜色 API |
| **P4** | **生命周期显式且有代价** | session 必须开关 |

## 2. 我们的三通道（把 P1–P4 落到本项目）

### 2.1 通道定义（载体先验，容量写死）

| 通道 | Nothing 对应 | **载体（先验约束）** | **容量上限（写死）** | 感知 |
|---|---|---|---|---|
| **C1 光** | Glyph LED | **顶栏状态点（8×8px）+ 窗口左边缘 1px 光带** | **顶栏点只能表达 5 种状态机；边缘光只能表达 3 种** | **余光** |
| **C2 形** | Micrographics / `displayProgress` | **播放栏左侧，一条 24px 高的路径画布**（宽 ≥ 320px） | **最多 6 段**（解码/源率/转换/DSP/输出/BitPerfect） | 扫视（1 秒） |
| **C3 字** | 屏幕正文 | 全界面 | 无上限，但**需要注视** | 注视 |

### 2.2 C1 的 5 个操作（照搬 GDK，不发明）

| 操作 | 对应 GDK | 本项目用法 | `prefers-reduced-motion` 降级 |
|---|---|---|---|
| **全暗** | `turnOff()` | 无曲目 / 引擎未连接 | 不变 |
| **常亮** | `toggle()` | 已装载未播 / 暂停 | 不变 |
| **呼吸** | `animate()` | **播放中**（周期 4s） | **→ 常亮** |
| **进度** | `displayProgress()` | 加载 / 扫描 / seek | **→ 离散步进**（每 500ms 跳一格） |
| **进度 + 全亮** | `displayProgressAndToggle()` | 扫描中 + 引擎已就绪 | 同上 |

> **只有 5 个，且每个都有降级路径。** 这是 P2 的纪律——**不许为某个新状态发明第 6 个操作**；不够用就说明该扩 C2。

### 2.3 C1 的 4 维度（照搬 GDK 的编码思路）

| 维度 | GDK | 本项目 |
|---|---|---|
| **通道（空间）** | `channel[]` | **顶栏点** vs **窗口边缘光**（两者可独立） |
| **时长** | `period` | 闪光持续 200ms（状态切换）/ 呼吸半周期 2s |
| **计数** | `cycles` | **用闪几下编码**：1 次=状态切换，2 次=xrun，3 次=设备变更 |
| **节奏** | `interval` | **快=紧急**（错误 3 次/秒）/ **慢=提示**（降级 1 次/2秒） |

**关键纪律（P3）**：**C1 不使用颜色区分状态**。颜色只在 C1 上表达"严重级别"（白/琥珀/红），**不表达"是什么状态"**——那是节奏与计数的职责。

## 3. 完整状态编码表（穷举 `protocol.ts`）

**完整性的定义**：`protocol.ts` 里的每一个 `ev`、每一个 `state`、每一个 `error code` 都必须在下表中出现。

### 3.1 播放状态（C1 承载）

| 引擎状态 | 来源字段 | **C1 操作** | C1 细节 | C2 | C3 |
|---|---|---|---|---|---|
| 无曲目 | `playState: 'no-track'` | `turnOff` | 全暗 | 空轨道 | — |
| 引擎未连接 | `engineUp: false` | `turnOff` | 全暗 | 空 | `connecting…` |
| 引擎就绪 | `ev: 'ready'` | `toggle` | 点常亮（低亮度） | 一段实线 | `engine ready · vX` |
| 已装载未播 | `loadedTrackId` 有值 | `toggle` | 点常亮 | 静止 | 曲名 |
| **加载中** | `playState: 'loading'`（intent 在途） | `displayProgress` | 顶栏点 `0→100%` 填充 | **逐格填充** | — |
| **播放中** | `state: 'playing'` | `animate` | **呼吸 4s** | **光点沿路径移动** | 曲名 + 时间 |
| 暂停 | `state: 'paused'` | `toggle` | 常亮（不呼吸） | 静止，当前格高亮 | — |
| **Seek 中** | `seekPending: true` | `displayProgress` | 快速填充到目标 | 目标格闪烁 | 目标时间 |
| 自然播完 | `ev: 'ended'` `reason: 'eof'` | `animate`→`turnOff` | 呼吸→一次长淡出 | 满格 | — |
| 已停止 | `state: 'stopped'` | `toggle` | 同「已装载未播」 | 静止 | — |

### 3.2 音质状态（C2 承载 —— 本系统的灵魂）

**这条路径有 6 段，每段都有明确语法（P3：几何，非颜色）**：

```
  [解码] ── [源率] ── [转换] ── [DSP] ── [输出] ── BP
     ●        ││        ────      ～～       ○       ━
```

| 段 | 语法（纯几何） | 语义 |
|---|---|---|
| **解码** | 实心方 = 已解码；空心方 = 未装载 | 这一环工作了吗 |
| **源率** | **竖线高度**表示采样率（44.1k 矮 / 96k 高 / 192k 最高） | 源是什么 |
| **转换** | **直线 = 直通**；**折线 ∧ = 重采样** | 有没有被弯折 |
| **DSP** | **无 = 直通**；**波浪线 ～～ = EQ/RG 生效** | 信号有没有被改过 |
| **输出** | **实心圆 = 独占**；**空心圆 = 共享**；**圆+括号 = 蓝牙** | 走的哪条路 |
| **BP** | **整条连成不中断实线 = bit-perfect**；任一处虚线/折线/波浪 = 否 | 全链无改动 |

#### 3.2.1 音质状态判定表（穷举）

| 引擎报告 | C2 图示 | C3 文字 | C1 |
|---|---|---|---|
| `bitPerfect: true` | `●─││────●─━` | `独占 · 96k/24bit · 原始信号` | 稳定 |
| `resampled: true` | `●─││─∧──○` | `44.1k → 48k 重采样` | 稳定 |
| `outputMode: 'shared'` | `●─││────○` | `共享模式` | 稳定 |
| `degradeReason` 存在 | `●─││─┄┄─○`（**虚线**） | **降级原因原文** | **琥珀慢闪** |
| `isBluetooth: true` | `●─││───(○)` | 设备名 + `蓝牙` | 稳定 |
| `xrunCount > 0` | 路径上一处 **抖动标记** | `xrun N` | **闪 2 次** |
| `hasExclusive: false` | 输出段**永久空心** | `本设备不支持独占` | — |
| `exclusiveFormats` 受限 | 源率段**被框住** | `仅支持 48k 独占` | — |
| 错误 `ERR_DEVICE` | **路径断开（缺口）** | 错误原文 + 下一步 | **红 + 急闪 3 次** |
| `fatal` | 全段熄灭 | 完整错误 | **红 + 常亮** |

> ⭐ **最重要的一条决策：`degradeReason` 用虚线，不用红色。**
>
> 你的机器**永远无法 bit-perfect**（实测：驱动不触发缓冲区事件）。如果降级 = 红色 = 错误，**界面就永远在报错**，红色会失去信号价值。
> **虚线表达"路是通的，中间有东西经过"——诚实，且不制造焦虑。**
> **红色只留给真正失败**（`ERR_DEVICE` / `fatal`）。

### 3.3 设备与系统状态

| 状态 | 来源 | C1 | C2 | C3 |
|---|---|---|---|---|
| 扫描中 | `scan_progress` | `displayProgress` | 逐格填充（N/M） | `扫描 40/91` |
| 扫描完成 | `scan_done` | 闪 1 次 | 满格 | `曲库就绪 · 91 首` |
| 设备切换 | `device_changed` | **闪 3 次** | 路径重绘 | 新设备名 |
| xrun | `ev: 'xrun'` | **闪 2 次 + 抖动** | 抖动标记 | `xrun N · buffer Mms` |
| 命令在途 | `pendingRequests > 0` | 点脉冲（慢） | — | — |
| 协议错误 | `protocolError` | 红急闪 | 路径断开 | 完整文本 |
| 日志 | `ev: 'log'` | — | — | 控制台（不进界面） |

### 3.4 能力自报（`EngineCapabilities`）

| 能力 | 表达 |
|---|---|
| `exclusive: true` | C2 输出段**可画实心圆** |
| `exclusive: false` | 输出段**永久空心**（**这是事实，不是错误**） |
| `shared: true/false` | 空心圆可用性 |
| `resampler: true` | 转换段**可画折线** |
| `dsp: false` | DSP 段**不画**（不是画个"关闭"） |
| `queue` / `seek` | 对应控件可用性 |

> **原则（P1）**：**界面只画引擎声明支持的东西。** 引擎没说的，界面不假装有。

## 4. ⭐ 强制层：让"系统"成为系统（这一章是 v4 缺的）

**v4 是一份漂亮文档，但没有强制力。** ECHO 的做法值得整块学习——**"系统"不是写下来的，是机器强制的**。

### 4.1 ECHO 已验证的机制（一手证据）

```
theme-contract.md 里写着：
  · check:theme-colors 脚本接进 npm run lint
  · 新增 CSS 用字面色 → lint 失败
  · scripts/theme-color-baseline.json 是"已计数基线"
  · 基线之上再加硬编码颜色 → 失败
  · 逃生口：/* theme-color-allow: reason */
```

**它的三个性质值得照搬**：

| 性质 | 效果 |
|---|---|
| **语义令牌，不是固定色** | `--theme-page-bg` 而非 `#111` → 亮/暗主题自动成立 |
| **CI 强制** | 违反就红，不靠人自觉 |
| **棘轮（ratchet）** | 基线只能降不能升 → **遗留债不会增长** |

### 4.2 我们的落地（三步）

**第 1 步：令牌契约**（文件名建议 `app/src/renderer/src/styles/tokens.css`）

```
语义层（唯一允许被组件使用的）：
  --c1-*        光通道：ok / warn / error / idle
  --c2-*        形通道：path-line / path-dash / path-node-on / path-node-off / path-fill
  --c3-*        文字：primary / secondary / muted
  --surface-*   面：app / page / panel / player / field
  --radius-*    4 / 8 / 12
  --ease-*      四条继承 + 两条新增
  --dur-*       状态 200 / 手势 220 / 几何 400 / 环境 600
禁止组件直接写：
  · 十六进制颜色
  · rgba() 字面量
  · 除 --duration/--ease 之外的时序字面量
```

**第 2 步：lint 规则**（照 ECHO 的形态）

```jsonc
// package.json
"scripts": {
  "check:tokens": "node tools/check-tokens.mjs",
  "lint": "eslint . && npm run check:tokens"
}
```

```js
// tools/check-tokens.mjs —— 检查 CSS/TSX 里的字面颜色与时序
// 1. 扫描 src/renderer/**/*.{css,tsx}
// 2. 命中 /#[0-9a-fA-F]{3,8}\b|rgba?\(/ 且不在 tokens.css 内 → 违规
// 3. 命中 /transition:\s*all|cubic-bezier\(|ease-in\b/ → 违规
// 4. 逃生口：同一行或上一行有 /* token-allow: <理由> */ → 跳过并记录
// 5. 与 tools/token-baseline.json 比对：
//    · 现有违规数 > 基线 → exit 1
//    · 现有违规数 < 基线 → 提示可下调基线（不 exit 1）
```

**第 3 步：棘轮基线** `tools/token-baseline.json`

```json
{
  "generatedAt": "2026-10-15",
  "note": "只能下调。新增违规会让 lint 失败。",
  "files": { "src/renderer/src/styles/theme.css": 0 }
}
```

### 4.3 为什么这比"写一份规范"重要

| | 只有文档（v4） | 文档 + 强制（v5） |
|---|---|---|
| 新增页面写死 `#111` | 没人发现 | **lint 红** |
| 半年后颜色漂移 | 必然 | **不可能**（基线棘轮） |
| 亮色主题 | 要手工全查 | 令牌自动成立 |
| **两个 AI 并行开发** | **必然分叉** | **同一契约** |

> ⚠️ **这条对两个 AI 尤其关键**：它们**看不到对方的代码**（CONTRACT §0 P8）。
> 令牌契约是**唯一能让两边产生一致视觉的机制**——因为违反会被机器拦下，而不是等合并时才发现两套颜色。

### 4.4 第三条强制：C2 的语法检查

C2 的路径是**数据驱动的**（由引擎状态算出 6 段），所以它的正确性可以被**单元测试**：

```ts
// 断言：给定引擎状态，路径语法唯一确定
expect(encodePath({ outputMode: 'shared', resampled: false, bitPerfect: false }))
  .toBe('●─││────○')          // 不得出现折线/虚线

expect(encodePath({ resampled: true })).toContain('∧')      // 重采样必有折线
expect(encodePath({ degradeReason: 'x' })).toContain('┄')   // 降级必有虚线
expect(encodePath({ bitPerfect: true })).not.toMatch(/[∧┄～～]/)  // BP 全链无改动
```

**这四条断言把 §3.2 的判定表变成了可执行的规格。** 这是"系统"的最终形态：**不是描述状态，而是能验证状态被正确编码**。

## 5. Apple 层：光感 / 动效 / 交互

Nothing 给**编码**（什么状态），Apple 给**物理**（状态之间怎么过渡）。

### 5.1 光感

| 用途 | 规则 | 依据 |
|---|---|---|
| **呼吸** | 周期 **4s**，亮度 0.5↔1.0，`ease-in-out`（**不用正弦**——正弦在极值处太慢） | 北欧：慢即安静 |
| **进度填充** | `linear`（恒定运动） | `animate` §5 |
| **状态闪光** | 200ms，`--ease-out-strong` | Apple：反馈要即时 |
| **氛围光** | 播放 `opacity 0.55` / 暂停 `0.28`，过渡 600ms | Apple §13：反馈与因果同帧 |

**硬规则（Apple §13 因果性）**：
> **C1 的每一次变化必须由真实事件触发**（`state` / `xrun` / `device_changed` / `scan_progress`）。
> **禁止"为了好看"的循环动画**——无因果的光会稀释 C1 的信噪比，违反 R1。

### 5.2 动效（频率门控 + 可打断）

| 交互 | 频率 | 决定 |
|---|---|---|
| 空格 / ←→ | **100+/日** | **零动画** |
| 列表 hover | 数十次/日 | **仅颜色**，无位移 |
| **C1 模式切换** | 每次状态变化 | **不插值，跳变**——光只有亮/灭，跳变才符合它的物理 |
| **C2 几何形变** | 切歌 / 换设备 | **动**（最有价值的动效） |
| 进度条拖动 | 手势 | 1:1 跟手 + 弹簧 |

```css
/* C2：采样率竖线的高度变化 —— 像一根被拨动的弦 */
.c2-bar-src { transition: height var(--dur-geom) var(--ease-immerse); }
/* C2：直线↔折线 —— 用 path 变形 */
.c2-seg-path { transition: d var(--dur-geom) var(--ease-in-out-screen); }
```

### 5.3 交互（进度条是唯一需要复杂手势的地方）

| 环节 | 做法 | 依据 |
|---|---|---|
| 抓取 | `setPointerCapture` + **尊重抓取偏移** | Apple §2 |
| 拖动 | 1:1 跟随 + **时间码持续反馈** | Apple §1 |
| 边界 | **橡皮筋**（渐进制动，不硬停） | Apple §9 |
| 释放 | **速度投影**决定落点 | Apple §6 |
| 打断 | 从**当前显示值**继续，不从目标值 | Apple §3 |

```js
// Apple 的投影函数（不是物理课本的 v²/2a）
function project(v, d = 0.998) { return (v / 1000) * d / (1 - d); }
const target = clamp(current + project(releaseVelocity), 0, duration);
```

**其余交互遵守「仪器按钮」纪律**（Nothing 主导）：
- 按下反馈用**变亮**（`rgba(255,255,255,0.07)`），**不用 `scale`**——仪器按钮不缩
- **焦点环固定高对比白**，**不得用强调色**（浅色封面上会消失）

## 6. 北欧层：只做空间与材料

**北欧不参与造型**（这是 v3-still-water 的错误）。

### 6.1 空间

| 规则 | 做法 |
|---|---|
| 间距表达归属 | 同组 `4px` / 组间 `16px` / 区段 `40px`。**用空白分组，不用线框** |
| 一屏一个重心 | 播放中 → 重心在 C2；浏览中 → 重心在列表。**不得同时两处发光** |
| 网格只用于数据对齐 | 列表轨道对齐（`64px \| 1fr \| 240px \| 72px`），**不画装饰性网格线** |

> **撤销 v3-signal 的"工业网格线"**：Nothing 的网格是**真实硬件结构**，不是画的线。
> 在软件里画满网格线 = 模仿它的**产物**。

### 6.2 材料（唯一一层）

```css
.ambient {
  background: radial-gradient(58% 58% at 50% 52%, var(--cover-color-soft), transparent 72%);
  filter: blur(64px);
  opacity: var(--ambient-opacity);   /* 播放 .55 / 暂停 .28 */
  transition: opacity var(--dur-env) var(--ease-in-out-screen);
}
```

**只有一层材料。** Apple §12：*"Never stack a light translucent surface on another"*。

### 6.3 时长（双轨）

| 类型 | 令牌 | 值 | 谁定 |
|---|---|---|---|
| 手势驱动 | `--dur-gesture` | **220ms** | Apple（跟手） |
| 状态切换 | `--dur-state` | **200ms** | Apple（反馈即时） |
| C2 几何形变 | `--dur-geom` | **400ms** | 北欧（几何变化需要时间看清） |
| 环境（氛围光） | `--dur-env` | **600ms** | 北欧（环境变化应该慢） |

> **双轨不是随意值**：**有手指在屏幕上 → Apple 的快；界面自己在说话 → 北欧的慢。**

## 7. 颜色（最后一步，且已被强制层约束）

**颜色在系统里是最后一步**——因为状态已由 C1/C2 唯一确定，颜色只剩两个功能：**强调** 与 **严重级别**。

```css

:root {
  /* 面 */
  --surface-void: #000000;   /* Nothing 的真黑：状态灯要在真黑上才准 */
  --surface-app:  #0A0A0B;
  --surface-page: #111112;
  --surface-panel:#17171A;

  /* C3 文字 */
  --c3-primary:   #FFFFFF;   /* 21:1 */
  --c3-secondary: #B0B0B4;   /* 9.6:1 */
  --c3-muted:     #757579;   /* 4.7:1 —— C2 标注用，达标 */

  /* C1 严重级别（只三级，不表达"是什么状态"） */
  --c1-ok:    #FFFFFF;       /* 正常态不着色 */
  --c1-warn:  #C9A227;       /* 降级：琥珀，慢闪 */
  --c1-error: #D71921;       /* 真失败：红，急闪。**仅此一处用红** */

  /* C2 形通道（几何为主，颜色只区分虚实） */
  --c2-line:      #EDEEF0;
  --c2-node-on:   #FFFFFF;
  --c2-node-off:  #4A4A4E;   /* 2.4:1 —— 仅轮廓，不承载信息 */
  --c2-fill:      #FFFFFF;

  /* 强调（当前项 / 激活） */
  --accent: #D71921;         /* **不跟封面**（Nothing 的点缀色是固定的） */

  /* 材质 */
  --cover-color-soft: rgb(110 110 120 / 0.5);  /* 只驱动氛围光 */

  /* 间距 / 圆角 */
  --radius-xs: 4px; --radius-sm: 8px; --radius-md: 12px;

  /* 时序（继承 theme.css 四条 + 新增两条） */
  --ease-immerse: cubic-bezier(0.16, 1, 0.3, 1);
  --ease-dissolve: cubic-bezier(0.4, 0, 1, 1);
  --ease-pop: cubic-bezier(0.34, 1.56, 0.64, 1);
  --ease-list: cubic-bezier(0.25, 0.1, 0.25, 1);
  --ease-out-strong: cubic-bezier(0.23, 1, 0.32, 1);
  --ease-in-out-screen: cubic-bezier(0.77, 0, 0.175, 1);
  --dur-gesture: 220ms; --dur-state: 200ms; --dur-geom: 400ms; --dur-env: 600ms;

```

**红色的系统级约束**：
> 红色**只用于 `ERR_*` / `fatal` / 协议错误**。**降级不用红**（用琥珀虚线）。
> 你的机器**长期处于降级状态**——红色会失去信号价值。

## 8. 通道降级（R3：预设计，不是补丁）

| 条件 | C1 | C2 | C3 |
|---|---|---|---|
| `prefers-reduced-motion` | 呼吸→**常亮**；进度→**离散步进**（500ms/格） | 形变→**瞬时切换** | **不变** |
| `prefers-reduced-transparency` | 不变 | 不变（C2 不透明） | 氛围光→**移除**，改纯色 |
| `prefers-contrast: more` | 提高对比，保留全部模式 | 线宽 +0.5px，加描边 | **不变** |
| 色盲（deuteranopia） | 琥珀/红**同时用闪频区分**（慢/急） | **零损失**（几何无色彩依赖） | 加文字标注 |
| 窗口 < 900px | 不变 | **压缩为 4 段**（合并解码+源率、DSP+输出） | 文字截断 |
| 亮色主题 | 呼吸/进度逻辑不变 | **零损失** | 令牌自动成立 |

> **关键性质**：C2 **完全不依赖颜色**（点/格/线/角度/虚实），所以**色盲与亮色主题下零损失**。
> 这是"几何即语义"带来的免费收益——**如果用颜色编码音质，这两个场景都要重做。**

## 9. 加新状态的规则（系统能生长的证明）

**这是"系统"与"皮肤"的根本区别：皮肤靠审美判断，系统靠流程。**

```
第 1 步  这个状态必须被感知吗？
        否 → 只进 C3（大多数内部状态）
        是 → 继续

第 2 步  二值（有没有异常）还是有结构（是什么）？
        二值 → C1
        有结构 → C2

第 3 步  C1：在 5 个操作（全暗/常亮/呼吸/进度/进度+全亮）里选一个。
        ★ 5 个都不够 → 停下。这是 C2 要扩容的信号，不是随手加颜色
        C2：能在现有语法（方/竖线/直折线/波浪/圆/虚实）里表达吗？
        ★ 不能 → 定义新几何基元，并更新 §3.2 语法表 + §4.4 断言

第 4 步  四项检验：
        · R1：截图糊成马赛克，还能判定吗？
        · R2：和已有状态的编码撞车了吗？
        · R3：禁用动效/去掉颜色后还完整吗？
        · 强制：token 检查通过吗？C2 断言补了吗？
```

**示例 —— M2 加入 EQ 后：**

| 问题 | 答案 |
|---|---|
| 要不要感知？ | **要**（破坏 bit-perfect） |
| 二值还是结构？ | 有结构（它改变了信号）→ **C2** |
| 怎么表达？ | 在转换段与输出段之间**插入波浪线段** `～～` |
| 检验 | `●─││─∧─～～─○` 可同时出现折线+波浪，**语法不冲突** ✅ |

**语法没变，只是多加了一种线段。** 这就是系统成立。

## 13. 采纳 Punctum 的技术细节（已核实）

**轴名（实测，不是我编的）**：`ROND` + `wght`。文件：

| 文件 | 用途 |
|---|---|
| `Punctum[ROND,wght].ttf`（262KB） | 可变字体，主用 |
| `Punctum-VF.woff2`（5.3KB） | **Web 用——体积极小** |
| `Punctum-Pixel{Thin..Black}.ttf`（49KB ×5） | **像素家族**（更硬的点阵感） |
| `Punctum-{Thin..Black}.ttf`（59KB ×5） | 静态实例 |

```css
@font-face {
  font-family: 'Punctum';
  src: url('/fonts/Punctum-VF.woff2') format('woff2-variations');
  font-weight: 300 900;
}
.c2-label {
  font-family: 'Punctum', ui-monospace, monospace;
  font-size: 10px;                    /* 必须小：放大后点变粗块 */
  letter-spacing: 0.08em;             /* 点阵字必须放开字距 */
  font-variation-settings: 'ROND' 0.0; /* 圆润度：0 = 最硬的方形点 */
}
```
