## 3. 忽略规则（`.gitignore` / `.gitattributes`）

`.gitignore` 分 7 组：依赖、构建产物、打包分发（体积大）、QA 痕迹、GraphFlow 状态、
机密/本机会话态、日志与系统垃圾。要点：

1. **没有 `*.png` / `*.exe` / `*.zip` 这类一锅端通配** —— 全部是具名路径，避免误伤截图与第三方源码。
2. `engine/third_party/**/build/`、`*.o`、`*.obj`、`*.a`、`*.lib`、`*.pdb`、`*.dll`、`*.exe` 单独排除：
   第三方**源码入库，构建产物不入库**。
3. 补充通用规则：`*.local`、`Thumbs.db`、`desktop.ini`、`.DS_Store`、`*.log`、`*.tmp`、`*.bak`、`~$*`、`.env*`（保留 `.env.example`）、`*.pem`/`*.pfx`/`*.p12`/`id_rsa*`。
4. 文件末尾有「必须入库，不要加规则」的注释块，防止后来者再加 `docs/screenshots` 或 `third_party` 规则。

`.gitattributes`：`* text=auto`；`*.ps1` / `*.bat` / `*.cmd` / `*.sln` / `*.vcxproj` 用 `eol=crlf`；
`png/jpg/jpeg/gif/ico/webp/mp3/flac/wav/ogg/mp4/webm/exe/zip/dll/lib/pdb` 标 `binary`。

> 副作用记录：`engine/third_party/taglib-2.3.2/` 自带 `.gitignore` / `.gitmodules` / `.github/**` 等 6 个隐藏元文件，
> Git 按 taglib 自己的规则忽略了它们（不影响构建，不含任何必要源码）。

## 8. CI

新增 `.github/workflows/ci.yml`（GitHub Actions）。

### app job（push / PR 必跑，`windows-latest`）
```
pnpm install --frozen-lockfile
pnpm typecheck
pnpm check:tokens
pnpm check:css
pnpm test:app
```
- Node 24 + pnpm 11，`cache-dependency-path: app/pnpm-lock.yaml`。
- Electron 二进制走 npmmirror（`ELECTRON_MIRROR` / `ELECTRON_BUILDER_BINARIES_MIRROR`），与仓库内 `.npmrc` 一致。
- `TWILIGHT_OFFLINE=1`：单测不联网。
- **不跑** `test:electron` / `test:player` / `test:listening` / `test:startup`：需要 Electron 单实例锁与独占音频设备，CI 上会互相打架且出声。

### engine job（`workflow_dispatch` 手动触发）
```
engine/tools/fetch-deps.ps1        # 从 GitHub 拉 TagLib / SoXR / dr_libs 等
engine/tools/build.ps1 -Configuration Release
engine/bin/twilight-engine.exe --selftest
```
注释里写明了：**第三方源码下载在部分网络环境下可能失败**（`raw.githubusercontent.com` 可达性），
失败通常不是代码问题，先看「Fetch third-party sources」这一步日志。因此不放到 push 必跑路径。
产物用 `upload-artifact` 上传 `twilight-engine.exe`。

### 13.1 `engine/tools/build.ps1`：把会造成构建失败的占位符改成真实探测

**修复理由**：publish-prep 在脱敏时把本机 Visual Studio 安装路径（形如 `<VS2026 安装根>\<某个安装目录名>\VC\Auxiliary\Build\vcvars64.bat`）
替换成了 `'<VS2026 安装目录>\VC\Auxiliary\Build\vcvars64.bat'`。这在**文档**里是正确写法，
但在这份脚本里它是**会参与 `Test-Path` 与 `call` 的可执行路径** —— 占位符永远不存在，
Ninja 分支会直接 `throw 'Ninja requested but no vcvars64.bat was found.'`，等于是把构建改坏了。
（publish-prep 的脱敏是批量文本替换，未能识别"这里是可执行路径不是注释"，这条责任在清洁工侧。）

**修复方式**：改为 **vswhere 自动探测 Visual Studio**（`%ProgramFiles(x86)%\Microsoft Visual Studio\Installer\vswhere.exe`
+ `-latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64`），探测不到时再兜底扫描常见安装目录。
已实测：语法 PARSE 0 错误，函数实跑返回本机 VS 路径。

### 13.2 `CONTRACT.md §7` 与 `docs/BRIEF-A-engine.md §6`：构建环境段落中性化

补完 publish-prep 批量替换后残留的构建环境段落（原含本机 VS 安装路径、只读工具目录等具体路径）。
**只改路径字符串，未动任何契约语义、字段名或错误码。**

### 13.3 `engine/PROGRESS.md:2002` 与 `CONTRACT.md` 残留清理

清掉最后几处漏网的机器路径。复核结果：**待入库文本文件 personal-path hits = 0**（Lead 与 publish-prep 各自独立复跑，结论一致）。

### 13.4 `app/resources/runtime/NODE-LICENSE.md`：换掉错误的许可汇编

**原状**：该文件的内容是 **Blender 的许可汇编**（与 Node.js 无关），属于打包资产里的错误文件。
**现状**：已换为 **Node.js v24.19.0 官方 LICENSE**（157,606 B），并在 `runtime/THIRD-PARTY-NOTICES.txt` 补了 **LGPL-3.0 组件条目**。

> 因此这条修改**不影响待入库清单**（复核确认仍为 1217 文件 / 27,730,785 B）；它影响的是**官方安装包**里的许可合规。

### 13.5 CI 首跑失败与修复（GitHub runner 无 GPU）

**现象**：push 后 GitHub Actions 第一次跑 **失败**（其余 473 条全绿，只挂 1 条）。

**根因（不是代码逻辑，是环境）**：GitHub 的 `windows-latest` runner **没有 GPU**。
`app/tools/artwork.test.mjs` 与 `app/tools/frequency-native.test.mjs` 会**真的拉起一个 Electron 进程**跑原生解码/频响，
Chromium 的 GPU 进程启动失败（`GPU process launch failed: error_code=18`），连带 network service 崩溃，
artwork 用例超时 → exit 1。

**修复原则**：**不是跳过 CI**（不 `--test-name-pattern` 排除、不 `continue-on-error`），而是修根因 —— 让这两条测试在无显卡机器上也走软件渲染。

| # | 文件 | 改动 |
| --- | --- | --- |
| 1 | `app/tools/artwork.test.mjs`、`app/tools/frequency-native.test.mjs` | 生成的 Electron 脚本里加 `app.disableHardwareAcceleration()` + `app.commandLine.appendSwitch('disable-gpu')`，并写中文注释说明「CI runner 无显卡，GPU 进程失败会拖垮渲染进程」 |
| 2 | `.github/workflows/ci.yml` | Unit tests 步骤补 `ELECTRON_DISABLE_GPU: "1"` 作环境兜底，并加注释说明为什么需要 |

**验证**（publish-prep 独立复跑，2026-10-20）：
- 这两条单独跑 → `tests 2 / pass 2 / fail 0`，exit 0（1.26 s）
- 全量 `pnpm test:app` → `tests 474 / pass 474 / fail 0`，exit 0（19.9 s）
**对这类的通用结论**：凡是「单测里真拉起 Electron」的用例，CI 上都要显式关硬件加速；
本项目里这样的用例有 2 条，已覆盖。其余 e2e（`test:electron` 系列）本来就不进 CI（单实例锁 + 独占音频设备）。
