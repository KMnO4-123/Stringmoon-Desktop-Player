## 0. 一句话

**Nothing 的信息坦诚 + Apple 的物理动效 + 北欧的静默留白。**

前两者提供「怎么动」，北欧提供「什么时候不该动」。三者的交集是一句话：

> **界面是一块安静的玻璃，声音穿过它，你不该注意到它。**

## 1. 三种语言，各取什么、各拒什么

| 来源 | **取** | **拒** | 为什么 |
|---|---|---|---|
| **Nothing** | ① **信息坦诚**：把设备/格式/状态如实摆在界面上（它标榜透明后壳）<br>② **等宽字承载数字与规格**<br>③ **点阵/网格作为结构**，不是装饰<br>④ 黑底上的**单一点缀色**<br>⑤ 红色只用于"这里需要你注意" | ④ 它的**字形化图标与闪烁灯**（`*`、`+` 那种）——太吵<br>⑤ 它的**高饱和红**直接铺开——我们只用它做"降级/错误"<br>它的**硬件参数炫耀式排版** | Nothing 的坦诚对我们**正中要害**：你的引擎能报 `bitPerfect` / `resampled` / `sourceSampleRate` / `degradeReason` / `xrunCount`——**这些数字现在没地方去**。 |
| **Apple** | ① **物理动效**：弹簧、速度继承、可打断（`apple-design` 全文）<br>② **材质分层**：`backdrop-filter` 译作层级，不是炫技<br>③ **光学字体**：字号相关的字距/行高<br>④ **克制的默认**：`damping 1.0` 无过冲<br>⑤ `prefers-*` 三件套 | 它的**圆角全家桶**（我们只用 3 档）<br>它的**毛玻璃堆叠**（我们只允许 1 层）<br>「拟物」倾向 | 你的 SPEC §5.6 已明确「**不是毛玻璃，是湿玻璃**」——这条**保留**，Apple 的材质章节正好给了它的技术依据。 |
| **北欧** | ① **留白即结构**：用空白分组，不用边框<br>② **低饱和自然色**：雾灰、苔绿、霜蓝、陶土<br>③ **一个"重心"**：每屏只有一处视觉重量<br>④ **耐心**：允许 400–600ms 的过渡（不是所有东西都要 150ms）<br>⑤ **光的存在感**——漫射的、无方向性的 | 它容易滑向的**性冷淡 = 没有信息**（与 Nothing 的坦诚冲突）<br>它的**完全无障碍**（我们仍要键盘/读屏） | 北欧解决三家里**唯一没人解决**的问题：**什么时候不该动**。 |

### 1.1 三者的真实冲突，以及怎么判

| 冲突 | 谁让 | 判据 |
|---|---|---|
| Nothing 要**高对比、黑底白字** vs 北欧要**柔和低饱和** | 各让一步 | **结构用高对比（文字/数字），环境用低饱和（背景/材质）** |
| Nothing 要**信息全露** vs 北欧要**留白** | 北欧让 | **默认层只留"此刻重要"的，规格收进悬停/展开**（§5.3 三层信息深度） |
| Apple 要**可打断、有速度** vs 北欧要**静默** | 都不让 | **手势驱动的一律可打断（Apple）；非手势的用长而缓的曲线（北欧）** —— 见 §4.2 的时长双轨 |
| Nothing 的**工业网格** vs Apple 的**圆润材质** | Nothing 让 | **网格只出现在数据排布（列表/仪表），不出现为边框** |

## 2. 色彩：把「澄明之境」的蓝，换成北欧的霜

现行 `theme.css` 是暖蓝强调色（`#6ea8b8`）+ 深空蓝黑三层。新方案**保留三层深度的结构**，但把色相拉到**中性偏冷**，并把强调色交给**封面取色**（Nothing 的坦诚：颜色应该来自音乐本身）。

### 2.1 基底（暗）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg-far` | `#0A0B0D` | 最远层（比原 `#0b0c10` 更中性，去掉蓝偏） |
| `--bg-mid` | `#101215` | 内容层 |
| `--bg-near` | `#17191E` | 浮起层 |
| `--bg-glass` | `rgba(23, 25, 30, 0.72)` | 湿玻璃底（配合 §3 三层材质公式） |

> **为什么去掉蓝偏**：原方案的蓝是「水」的隐喻；北欧的霜是**无色的**。把色相让给封面，界面本身退到中性——这也让 Nothing 的单点缀色更成立。

### 2.2 文字（四级，Nothing 的坦诚要求可读）

| 令牌 | 值 | 对比度（对 `--bg-far`） | 用途 |
|---|---|---|---|
| `--text-primary` | `#EDEEF0` | **≈15.8:1** ✅ AAA | 曲名、当前值 |
| `--text-secondary` | `#A8ABB2` | ≈7.3:1 ✅ AAA | 艺术家、次要值 |
| `--text-muted` | `#6B6F77` | ≈3.6:1 ✅ AA（大字） | 标签、单位 |
| `--text-dim` | `#4A4D54` | ≈2.1:1 ⚠️ | **仅非语义装饰**（分隔、禁用） |

> ⚠️ **`--text-dim` 不许承载任何信息**。原方案用它做 `LIBRARY`（封面占位）——那是信息，要升到 `--text-muted`。

### 2.3 强调色：**由封面驱动，三档光学处理**

**这条是三种语言的交汇点**——Nothing 的单色点缀、北欧的自然色、你的 SPEC §5.1「封面取色 → 饱和 −15% / 明度 60–70%」全都指向同一件事。

```css
:root {
  /* 由 ColorExtractor 在封面变化时写入 --accent-raw（RGB 三元组） */
  --accent:       rgb(var(--accent-raw));
  --accent-soft:  color-mix(in oklab, rgb(var(--accent-raw)) 62%, var(--bg-mid));
  --accent-faint: color-mix(in oklab, rgb(var(--accent-raw)) 22%, transparent);
  --accent-line:  color-mix(in oklab, rgb(var(--accent-raw)) 45%, transparent);
}
```

**兜底色**（无封面时）：`--accent-raw: 122 156 168`（霜蓝，比原 `#6ea8b8` 更灰）。

**语义色**（Nothing：红色只在需要你注意时出现）：

| 令牌 | 值 | 唯一用途 |
|---|---|---|
| `--warn` | `#C9A227`（琥珀） | 降级提示（如"已回退共享模式"） |
| `--error` | `#C4564B`（陶土红） | 失败 / 协议错误（取自原「水墨」主题的朱砂） |
| `--ok` | `--accent` | 正常态**不用绿色**——避免"到处都是状态灯" |

## 3. 材质：湿玻璃的三层公式（Apple 材质 + 北欧的克制）

**硬规则：全界面最多一层 `backdrop-filter`。** 原 SPEC §5.6 禁止毛玻璃堆砌，这条在 Web 栈上有了技术依据——`backdrop-filter` 每层都是独立合成层，堆叠会掉帧。

| 层 | 场景 | 配方 |
|---|---|---|
| **M0 环境** | 背景、侧栏底 | **无 blur**。`linear-gradient` + 极淡径向光（北欧：光是无方向的） |
| **M1 浮层** | 播放栏、顶栏、队列玻璃板 | `backdrop-filter: blur(24px) saturate(140%)` + `--bg-glass` |
| **M2 卡片** | 封面、正在播放 | 无 blur；用**内描边 + 边缘辉光 + 环境遮蔽**（原湿玻璃三要素，见 §7） |

```css
/* M1：唯一允许 blur 的一层 */
.material-float {
  background: var(--bg-glass);
  backdrop-filter: blur(24px) saturate(140%);
  /* 顶部亮边 = 光打在材质上（Apple §12） */
  border-top: 0.5px solid rgba(255, 255, 255, 0.10);
}

/* 滚动边缘渐隐，代替 1px 硬分隔线（Apple §12） */
.scroll-fade-top {
  mask-image: linear-gradient(to bottom, transparent 0, #000 24px);
}
```

> ⚠️ **`prefers-reduced-transparency: reduce` 时 M1 退化为不透明纯色**（`--bg-near`），这是无障碍硬要求，不是可选项。

## 4. 动效：Apple 的物理 + 北欧的耐心

### 4.1 门控表（`animate` 的频率判据 + Nothing 的坦诚）

| 交互 | 频率 | 决定 |
|---|---|---|
| 空格播放/暂停、←/→ seek | **100+ 次/日** | **零动画**（`animate` 硬规则：键盘动作是"取消资格"项） |
| 列表项 hover | 数十次/日 | 仅**颜色 + 极轻阴影**，无位移 |
| 曲目切换 → 现在播放区 | 数十次/日 | **可以动**：这是"空间一致性"（你双击的那一行，内容从那里升起） |
| 歌词逐字高亮 | 每首数百次 | **动，但用 CSS**（离主线程，见 §4.3） |
| 队列面板开合 | 偶尔 | 标准动画 + 可打断 |
| 首次启动 / 曲库扫描完成 | 罕见 | **这里才允许"愉悦预算"** |

### 4.2 时长双轨（调停 Apple 与北欧的冲突）

```
手势驱动 → 150–250ms，可打断，继承释放速度（Apple）
非手势   → 320–520ms，缓入缓出，不着急（北欧）
```

**关键：这不是两个随意值，而是"是否有手指在屏幕上"的区分。** 有手势时用户在看，要跟手；没有手势时界面自己在说话，可以从容。

### 4.3 工具选择（`animate` §3：最便宜的能用就行）

| 需求 | 工具 | 理由 |
|---|---|---|
| hover / press / 颜色 / 状态类切换 | **CSS transition** | 最便宜 |
| 歌词逐字高亮 | **CSS transition**（`background-size` 或双层 `clip-path`） | **必须留 CSS**——它每 100ms 变一次，JS 会掉帧 |
| 队列面板开合、可打断 | **CSS transition + 从当前值重设** | 能被打断（`@keyframes` 不行） |
| 拖拽进度条释放 | **弹簧**（Motion，仅在释放瞬间） | 需要速度继承 |
| 曲目切换的内容升起 | **`@starting-style` + CSS** | 无需 JS 状态 |

> ⚠️ **不引入 Motion 库，除非进度条拖拽要做速度投影**。你的项目现在没有动效库，为一个手势装一个库要先证明它值得。

### 4.4 曲线（继承现有令牌，**不新建**）

现有 `theme.css` 已有四条曲线，**保留它们**（`animate` 硬规则 3：扩展现有令牌，不要分叉）：

| 现有令牌 | 值 | 新方案里的用法 |
|---|---|---|
| `--ease-immerse` | `cubic-bezier(0.16, 1, 0.3, 1)` | **默认**（入场、歌词、面板）——它就是强 ease-out |
| `--ease-dissolve` | `cubic-bezier(0.4, 0, 1, 1)` | 出场 / 溶解 |
| `--ease-pop` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | **仅**"抓取释放"类（有动量的） |
| `--ease-list` | `cubic-bezier(0.25, 0.1, 0.25, 1)` | hover / 颜色 |

**新增两条**（`animate` 表格要求，且现有四条覆盖不到）：

```css
--ease-out-strong: cubic-bezier(0.23, 1, 0.32, 1);   /* UI 入场，比 ease-immerse 更锐 */
--ease-in-out-screen: cubic-bezier(0.77, 0, 0.175, 1); /* 屏内移动/形变 */
```

**禁止**：`ease-in`（`animate` 明令）、`transition: all`、`scale(0)`。

## 5. 布局：Nothing 的坦诚收进北欧的留白

### 5.1 骨架（保留现有三区，尺寸微调）

```
┌────────────────────────────────────────────────────────┐
│ 顶栏 52px   品牌 · 视图切换 · 目录 · 引擎状态            │  ← M1 浮层
├────────┬──────────────────────────────┬────────────────┤
│ 导航   │ 主区                          │ 信息栏         │
│ 196px  │ 列表 / 封面墙 / 歌词           │ 300px          │
│        │                              │                │
├────────┴──────────────────────────────┴────────────────┤
│ 播放栏 76px   封面 · 曲目 · 进度 · 控制 · 规格 · 音量     │  ← M1 浮层
└────────────────────────────────────────────────────────┘
```

| 变化 | 原值 | 新值 | 理由 |
|---|---|---|---|
| 顶栏 | 56px | **52px** | 北欧：减少常态占位 |
| 导航 | 200px | **196px** | 微调对齐 4 的倍数 |
| 播放栏 | 72px | **76px** | **为规格行腾出空间**（§5.3） |
| 信息栏 | 280px | **300px** | 现在播放需要更多横向 | 

### 5.2 留白即结构（北欧）

**删掉侧栏与主区之间的 0.5px 分隔线**（现 `theme.css:79`）。改用**背景层差**分组——这是北欧的核心手法：**用明度分层，不用线条切割**。

```css
/* 删：border-right: 0.5px solid rgba(255,255,255,0.03) */
/* 改：让 sidebar 落在 --bg-far，主区落在 --bg-mid */
.sidebar { background: var(--bg-far); }
.main    { background: var(--bg-mid); }
```

### 5.3 ⭐ 信息深度三层（调停 Nothing 的"全露"与北欧的"留白"）

**这是本方案最重要的结构决定。** 你的引擎能报很多数字，但**不能一次全摆出来**。

| 层 | 内容 | 何时可见 |
|---|---|---|
| **L1 永远可见** | 曲名、艺术家、进度、播放控制 | 常态 |
| **L2 状态诚实层** | **`bitPerfect` / `输出模式` / `源采样率→设备采样率`** | 播放栏右侧，**常驻但低对比**（`--text-muted`） |
| **L3 规格详情** | 位深、编码、设备名、缓冲、xrun 计数、降级原因 | **悬停/点击 L2 展开** |

```
┌─ 播放栏右侧（现状已有雏形：`共享 · 44.1k→48k 重采样`）──────────┐
│  L1:  测试曲目 001                    L2:  共享 · 44.1k→48k        │
│       Test Artist                            [▾] ← 点开 L3           │
│                                        位深 16 · FLAC · 缓冲 24ms │
└──────────────────────────────────────────────────────────────┘
```

**L2 的三态视觉**（Nothing 的坦诚，直接对应引擎的真实遥测）：

| 引擎状态 | L2 显示 | 颜色 |
|---|---|---|
| `bitPerfect: true` | `独占 · 96k · BP` | `--accent` |
| `resampled: true` | `共享 · 44.1k→48k 重采样` | `--text-muted` |
| `degradeReason` 存在 | `已降级 · <原因>` + `[▾]` | `--warn`（琥珀） |
| 设备打不开 | `输出不可用` | `--error` |

> **这是 Nothing 精神的核心落地**：把"我做不到 bit-perfect，因为你的驱动"**如实说出来**，而不是藏起来。你的引擎已经这么做了（PROGRESS 记录了看门狗降级），界面要接住它。

## 6. ⭐ 景深：本方案新增的四层体系

用户要求"加入景深"。但**景深不是模糊**——模糊只是景深的一个副产品。真正的景深是**四件事同时成立**：

| # | 手段 | 实现 | 感知 |
|---|---|---|---|
| **1** | **尺度差** | 远层元素 `scale < 1`，近层 `scale = 1` | 透视 |
| **2** | **清晰度差** | 远层 `blur(2–6px)` + `opacity` 降 | 焦点 |
| **3** | **运动视差** | 远层位移量 = 近层 × 0.15–0.3 | 纵深（**核心**） |
| **4** | **明度/对比差** | 远层压暗 8–12% | 大气透视（北欧的"雾"） |

### 6.1 静态景深（不依赖动效）

```
Z0  背景光晕         blur 40px,  opacity 0.5,  scale 1.06
Z1  主内容           blur 0,     opacity 1,    scale 1
Z2  浮层（播放栏）    blur 24px(backdrop), scale 1,  阴影 24–40px
Z3  覆盖层（队列）    blur 48px(backdrop) + 主内容 dim 0.95 + scale 0.98
```

**`Z3` 出现时主内容 `scale 0.98` 是关键**——Apple §12「push the background back/down」。**没有任何模糊也能感到深度**。

```css
.app-shell.overlay-open .main,
.app-shell.overlay-open .sidebar {
  transform: scale(0.98);
  filter: brightness(0.95);
  transition: transform 400ms var(--ease-immerse), filter 400ms var(--ease-immerse);
}
```

### 6.2 运动景深（鼠标视差 —— **必须门控**）

**这是"景深"从静态变成"活的"的关键**，也是最容易做坏的地方。

```css
/* 只在真有精确指针且不要求减少动效时启用 */
@media (hover: hover) and (pointer: fine) and (prefers-reduced-motion: no-preference) {
  /* 由 JS 写入 --px / --py（-1..1） */
  .app-shell {
    --parallax-far: 4px;   /* 远层位移幅度 */
    --parallax-mid: 2px;
  }
  .bg-glow  { transform: translate3d(calc(var(--px) * var(--parallax-far) * -1), calc(var(--py) * var(--parallax-far) * -1), 0); }
  .cover-art{ transform: translate3d(calc(var(--px) * var(--parallax-mid) * -1), calc(var(--py) * var(--parallax-mid) * -1), 0); }
}
```

**三条约束**（`animate` §4 + apple §9）：

1. **幅度 2–4px 上限**。超过 6px 就从"景深"变成"晕船"
2. **反向位移**（`-1` 倍）——近层跟随鼠标，远层逆动，这才是视差
3. **用弹簧收敛，不要直接绑 `pointermove`**（否则每帧都写样式，抖动）

```js
// 用弹簧把鼠标位置平滑到目标，再写入 CSS 变量
// damping 1.0（无过冲），response 0.4 —— apple-design 的 Move/reposition 档
```

> ⚠️ **`prefers-reduced-motion: reduce` 时整个视差必须关闭**（不是减弱）——这是前庭失调的硬红线。

### 6.3 歌词的景深（把 §7 的"浸入"升级为真正的 Z 轴）

现行实现是 `translateY + opacity + blur`。**加入尺度差后会真正确立前后关系**：

| 行 | `translateY` | `scale` | `blur` | `opacity` |
|---|---|---|---|---|
| 当前行（Z=0） | 0 | **1.00** | 0 | 1.0 |
| 相邻行（Z=+1） | ±14px | **0.96** | 0.6px | 0.55 |
| 更远行（Z=+2） | ±28px | **0.92** | 1.4px | 0.28 |
| 更远（Z≥3） | ±42px | **0.88** | 2.4px | 0.12 |

**尺度差 0.88–1.00 是刻意的窄区间**——超过 0.85 会像"缩小动画"，而不是"退到远处"。

### 6.4 封面：从"玻璃板"到"浮在水面"

现行 SPEC §5.3④ 已有玻璃板 + 倾斜。新方案加**两件事**：

1. **封面后方的色光**（`--accent` 的 40% 模糊投影）——让封面"照亮"身后的玻璃（Nothing 的"透光"）
2. **倾斜只在小角度**（`≤2°`，现行值保留），但**加 `perspective: 800px`**，否则倾斜看起来像剪切，不是旋转

```css
.cover-art {
  transform-style: preserve-3d;
  /* 父层 perspective 800px */
}
.cover-glow {
  position: absolute; inset: -8%;
  background: radial-gradient(60% 60% at 50% 55%, var(--accent-faint), transparent 70%);
  filter: blur(28px);
  z-index: -1;
}
```

## 8. 无障碍（硬要求，随方案一起交付）

```css
/* ① 减少动态：关掉所有位移与视差，保留透明度/颜色 */
@media (prefers-reduced-motion: reduce) {
  .app-shell * { animation-duration: 0.01ms !important; transition-duration: 120ms !important; }
  .bg-glow, .cover-art { transform: none !important; }   /* 视差必须整个关掉 */
  .lyrics-line { transform: none !important; filter: none !important; }
}

/* ② 减少透明：M1 浮层退化为不透明 */
@media (prefers-reduced-transparency: reduce) {
  .material-float { background: var(--bg-near); backdrop-filter: none; }
}

/* ③ 提高对比：给所有浮层加实线边界 */
@media (prefers-contrast: more) {
  .material-float { background: var(--bg-near); border: 1px solid rgba(255,255,255,0.28); }
  .scroll-fade-top { mask-image: none; }
}
```

**另外三条**：

- **焦点环不能丢**：现有方案里焦点环是强调色，现在强调色来自封面 → **焦点环必须用固定的高对比色**（`--text-primary`），不能跟封面走，否则浅色封面上会看不见
- **键盘全可达**：三区都要能 `Tab` 进出，播放栏所有控件可达
- **`--text-dim` 不承载信息**（见 §2.2）

## 9. 落地顺序（按性价比，不按视觉顺序）

| # | 步骤 | 成本 | 收益 |
|---|---|---|---|
| **1** | 换色彩令牌（§2）+ 删侧栏分隔线（§5.2） | 小 | **立刻**看出北欧的静 |
| **2** | **L2 规格层**（§5.3）接上引擎遥测 | 小 | **Nothing 精神落地**，且你已有全部数据 |
| **3** | 封面取色 → `--accent-raw`（§2.3） | 中 | 三种语言的交汇点 |
| **4** | 歌词 Z 轴景深（§6.3） | 中 | 视觉提升最明显的一处 |
| **5** | 队列开合 + 主内容后退（§6.1 `Z3`） | 中 | 景深的"活"的那半 |
| **6** | 鼠标视差（§6.2） | 中 | 锦上添花，**最后做** |
| **7** | 封面色光 + perspective（§6.4） | 小 | 细节 |

> **第 6 步排最后**的原因：它最容易做坏（幅度、门控、弹簧），而收益最小。**如果只做到第 5 步，方案已经成立。**
