> 工作目录：`<仓库根>\` · 你的目录：`<仓库根>\app\`

## 1. 你是谁，你负责什么

你是 **AI-B**，负责 Twilight Echo 的**应用侧全部**：

- **Electron 44 + TypeScript + React**，产出整个桌面应用
- **UI / 交互 / 动画**（设计语言叫「澄明之境」）
- **曲库展示**（数据来自引擎，你不管扫描）
- **平台账号接入**（网易云、Navidrome；Node API 服务端由主进程自动启动）
- **歌词**（取回、归一化、渲染成动画）
- **窗口/托盘/设置/登录态**

**你不负责**：音频解码、DSP、WASAPI、设备管理、标签读取。那是 AI-A 的活，它在 `engine\` 目录，你看不到它，它也看不到你。

**你和它之间只有一条通道**：`twilight-engine.exe` 的 stdin/stdout，JSON Lines 协议（`CONTRACT.md` §3）。

## 3. 硬边界（越界即冲突）

1. **禁止修改** `CONTRACT.md` 和 `docs\SPEC-v2.1.md`。它们是冻结契约，**双方只读**。
2. **禁止进入 `engine\` 目录改任何文件。**
3. **禁止自己扩展 JSON 字段名。** 契约里写的字段一字不差地用；你多写的字段对方会忽略，但别指望对方理解它。
4. **驱动引擎时：stdout 是协议流，不是日志流。** 解析时按行 `JSON.parse`，**任何一行解析失败都要当作引擎 bug 报出来**，不要静默跳过。
5. 需要改契约时：在 `docs\contract-requests.md` 追加一条（用文件里的模板），**然后等 owner 裁定**，不要自己动手改。
6. **不要把渲染进程变成 Node 环境。** 安全默认值关掉，用 `preload` + `contextBridge` 暴露白名单 API。

## 4. 你的第一个任务（M1 的应用侧）

按顺序做，**每一步都要能独立验证**。

### 第 0 步：壳起得来（先证明窗口能出）

在 `app\` 建 Electron + React + TypeScript 工程：

- `pnpm dev` 能起窗口
- 窗口尺寸合理（建议 1280×800 起，最小 900×600）
- 三区布局骨架按 SPEC §5.2 的尺寸摆出来：顶栏 56px / 导航栏 200px（可折叠）/ 主内容区 / 信息栏 280px / 播放栏 72px
- 深色基底 `#0B0C10`，先不追求视觉效果

**构建工具选型你自己定**（Vite 是常规选择）。要求只有一个：**`pnpm dev` 一条命令能起来**，并把命令写进 `app\README.md`。

### 第 1 步：假引擎（**这一步比看起来重要**）

写 `app\tools\mock-engine.mjs`：一个**假装自己是 `twilight-engine.exe`** 的 Node 脚本。

- 从 stdin 读 JSON Lines 命令，往 stdout 写 JSON Lines 事件
- 行为**严格按 `CONTRACT.md` §3**
- `hello` → 回 `ready`
- `scan` → 回 91 首（见下面「曲库数据」）
- `open` / `play` / `pause` / `stop` / `next` / `prev` / `seek` / `set_volume` → 回 `ok`，并周期发 `position` 与 `state` 事件
- **`play` 后要真的让 `position` 自己往前走**（定时器模拟），否则你的进度条写不了

**为什么必须写它**：AI-A 的引擎现在还不存在，而你不能等。**双方各自实现契约的另一侧，是这份契约真正生效的方式。**

### 第 2 步：曲库列表 + 播放控制

- 调 `scan`，把返回的曲目渲染成列表（虚拟列表先不做，91 条直接渲染）
- 双击曲目 → `open` → `play`
- 播放栏接上六个控制命令 + 音量
- 进度条随 `position` 事件推进，可拖拽 seek
- **`state` 事件是权威值**，UI 不得自行推断播放状态

**曲库数据**（两个来源，任一可用）：

- **首选**：AI-A 会输出 `engine\fixtures\library-91.json`（真实元数据）。**在它出现之前**，你自己从 `<测试曲库>` 生成一份占位 fixture（随便用个 JS 标签库，或先只取文件名），放进 `app\fixtures\`。等 A 的那份出现后替换。

> 那个目录里的文件名有几个坑：含空格与中文、有**连续多个空格**、有**带组合字符的 Unicode**（例 `Cytus - ͟͝͞Ⅱ́̕.flac`）、有些很长。**你的列表 UI 必须扛得住这些**——长标题截断、不换行错位、不撑破容器。

### 第 3 步：歌词渲染（M1 的视觉验收点）

M1 只要求"**歌词动起来**"，不要求做完所有效果。但要做对数据模型：

- 实现 `CONTRACT.md` §4.3 的**歌词归一化格式**（`Lyrics` 结构）
- 至少实现一种来源：**本地 `.lrc`**（和音频同目录同名）最简单，先做它
- 渲染：SPEC §5.3 效果 ⑤「歌词逐行浸入」——**当前行 `translateY(16→0)` + opacity + `blur(4→0)`，500ms，`cubic-bezier(0.16,1,0.3,1)`**；相邻行 15px、`#4A4A52`、`blur(0.5px)`；旧行上移 12px 溶解 400ms
- 行距不等（当前行 24px / 相邻行 12px）

> **这里有个好消息**：`blur()` 和 `backdrop-filter` 在 Chromium 里是**原生**的。原方案选 Slint 时这两条**做不到**（slint#2066 / #6021），正是换栈的原因。**你要把这些效果做足，做不到才是失败。**

### 第 4 步：把假引擎换成真引擎

当 AI-A 的 `twilight-engine.exe` 可用时：把 spawn 目标从 `mock-engine.mjs` 换成真 exe，**协议代码一行都不用改**。如果改了很多，说明前面没按契约做，回去对齐。

## 6. 「澄明之境」要点速查

完整规范在 v2.0 legacy §5，这里只放最容易做错的：

**色彩**：基底 `#0B0C10`；三层深度 远 `#0B0C10` / 中 `#111318` / 近 `#181A21`；强调色默认**从封面取色**，然后做光学处理（饱和 −15%、明度 60–70%、色相 +5% 蓝偏）。

**湿玻璃材质（不是毛玻璃！）**三要素：
1. 厚度：`inset 0 0 0 0.5px rgba(255,255,255,0.08)`；顶部 0.1 → 底部 0.04 渐变
2. 边缘辉光：左上角 radial，0.06 → transparent 70%
3. 环境遮蔽：投影 `rgba(6,8,18,0.6)`，模糊 24–40px，偏移 0–4px

**刻意避免**：毛玻璃堆砌、紫/蓝渐变、对称布局、圆形播放按钮、直线进度条、粒子/频谱背景、纯黑背景、模板化卡片、拟物 CD 盒。**「无卡片，只有层与光」**。

**动效铁律**：所有动效有物理依据；**除唱片旋转外绝不使用线性曲线**。

**九大效果的实现状态（这是换栈后的收益，别浪费）**：

| 效果 | 状态 |
|---|---|
| ① 光晕指针 | ✅ 可用：`cursor: none` + 自绘跟随元素 |
| ② 列表项悬浮 | ✅ 原生 |
| ③ 水滴进度条 | ✅ CSS + SVG |
| ④ 封面玻璃板（鼠标倾斜 ≤2°） | ✅ transform + 鼠标跟随 |
| ⑤ **歌词逐行浸入（含 blur）** | ✅ **原生 `filter: blur()`** |
| ⑥ 播放栏光带 | ✅ 原生 |
| ⑦ 队列玻璃板 | ✅ **原生 `backdrop-filter`** |
| ⑧ 迷你模式点穿 | ⚠️ 仍受限，先做「置顶 + 无边框」，点穿后置 |
| ⑨ 搜索光流 | ✅ 原生 |

## 7. 平台接入（M3 才做，但现在就要知道）

**不要现在做**，但架构上要给它留位置。

按 `CONTRACT.md` §4 的 `MusicProvider` 接口设计。关键事实（都已核实，别自己另搜一遍得出不同结论）：

| 事实 | 含义 |
|---|---|
| **Folia 的实际形态**＝前端 + 薄适配层 + **用户自备/内置 API 服务端** | 你也照这个做：Electron 主进程自动启动 API 服务端子进程 |
| **NeteaseCloudMusicApi 原版已 archived**（2024-02-28） | 用继任者 **`@neteasecloudmusicapienhanced/api`**（MIT，活跃） |
| **QQ 用 `@yakult-green-tea/qq-music-api`**（活跃 fork） | 但 QQ 风控最重，优先级最低 |
| 官方**没有**开放 API | 平台协议只能靠社区逆向实现，随时可能失效 → **本地 + Navidrome 必须始终可用** |
| 网易云扫码登录 = `unikey` + 轮询 | `qr/key` → `qr/create` → `qr/check`（800 过期 / 801 待扫 / 802 待确认 / 803 成功） |
| **端口不得硬编码** | 启动时取空闲端口，通过 IPC 告知渲染层；不要假设 3000/18080 |
| 凭据用 `safeStorage`，**Electron 46 起同步 API 已移除** | 现在就用异步版：`isAsyncEncryptionAvailable()` / `encryptStringAsync()` / `decryptStringAsync()` |

**风控约束是硬要求**（`CONTRACT.md` §5）：请求间隔 ≥1s、令牌桶、禁刷歌/自动签到/后台轮询歌单、收到 `-460` 立即停止该平台全部请求不重试。用户用的是**主力账号**。

## 8. 歌词数据源（M1 只用本地 LRC，其余后续）

优先级见 `CONTRACT.md` §4.4。要点：

1. 本地/内嵌歌词文件
2. **AMLL TTML DB** —— 逐词 TTML 事实标准，CC0-1.0，按歌曲 ID 直链：
   `https://raw.githubusercontent.com/amll-dev/amll-ttml-db/refs/heads/main/ncm-lyrics/<歌曲ID>.ttml`
3. 网易云 `yrc` —— 请求带 `yv=-1` 即返回字级：`[行起点,行时长](字起点,字时长,0)字`
4. **QQ QRC：不做**（需自建解密，性价比最低）
5. LRCLIB 只作**行级兜底**（其 `hasWordSync` 字段实测恒为 false）

**插值兜底必须如实标注**：只有行级数据时按字等分插值，并把 `wordByWord` 标为 `false`。**不要假装是原生逐字。**

## 9. 环境（本机实测，别猜）

```
Node               <系统工具目录>\node.exe
pnpm               %APPDATA%
pm\pnpm.ps1
git                <测试曲库父目录>\Git\cmd\git.exe
Electron           44.x（当前 stable 44.7.2）
```

**三条会绊人的：**

1. **`<系统工具目录>` 是只读 ACL** —— 绝对不要往那里装全局包（那是系统 Node 所在目录）。用项目内 `node_modules` 或 `pnpm` 的本地行为。
2. 本机 PowerShell 执行策略会挡 `.ps1` 直跑 → 用 `powershell -ExecutionPolicy Bypass -File`。
3. 网络：GitHub CDN 可能被墙，`gh-proxy.com` 前缀可用；**npm registry 正常**。

## 10. 不要自己发明的东西

这些**必须逐字照 `CONTRACT.md`**：

- 命令名与字段名（`cmd` / `ev` / `id` / `ok` / `error` / `data` …）
- **trackId 的消费方式**：引擎给什么用什么，**不要在本地重新生成 id**（要自己的 id 用 `ui_` 前缀，但仍以后端为准）
- **歌词归一化结构**（§4.3）—— 这是你和动画层之间的冻结接口
- **"降级不是错误"**：引擎 `outputMode` 变成共享 / `bitPerfect:false` 时**不是错误**，UI 要**明示状态**而不是弹错误框（SPEC §3.3 双模式明示）
