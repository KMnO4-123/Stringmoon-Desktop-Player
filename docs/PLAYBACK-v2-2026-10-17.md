## 0. 一句话结论

本轮把 ECHO NEXT 里**可测量、可落地**的专业音频功能移植进了引擎与应用（重采样档位 / dither 噪声整形 / 声道工具扩展 / 输出延迟档位），补齐了播放链路的三个真实缺口（**切歌延迟**、**播放记忆/恢复**、**ReplayGain 全链路接线**）与一个契约硬要求（**-460 风控熔断**）；并产出了一份**逐条带证据的功能落地审计**（88 条声称：49 已落地 / 6 部分 / 14 未落地 / 5 文档过时 / 14 本轮进行中，见 §5）。

关键转化（同机、同协议；before/after 见 §4）：
- **切歌**：引擎内部 shared 跨率 open 中位 **76.7ms → 1.1ms**（output opened 增量 0）；open→playing 中位 **83.9ms → 34ms**（达 ≤50ms 验收）。应用层「open 请求」before 198–386ms（混端点）→ after 见 §4（同端点 pin）。
- **深度播放**（immersive：歌词+频谱光带+唱片+meter+EQ）：渲染层等价优化后 Tab/GPU 见 §4；不降视觉频率。
- **ReplayGain**：从「用户以为有、实际 0 调用」变成「设置页开关 → analyze_loudness（缓存）→ set_replaygain（真峰值 preventClip）→ dspModules/bit-perfect 如实回显」。
- **播放记忆/恢复 + 下一首预热**：真 IPC + 持久化 + UI 入口；预热 8MB 实测 13ms，不打扰播放主线程。

## 1. 移植范围（做了什么 / 明确没做什么）

### 1.1 引擎（`engine/src`，exe 20:56:00 / 1,963,008B / SHA256 9DD47E13…）
| 项 | 内容 | 默认值 / 等价性 |
|---|---|---|
| E10 + E10b | 独占协商失败缓存（按设备+格式，device_changed 失效）；shared 跨采样率切歌不再整段重开 WASAPI | 输出模式语义不变；`state.bufferMs/periodMs` 如实 |
| feeder 等待 | 2–3ms 轮询 → 条件变量 timed wait（更早轮次已完成，本轮复核保留） | 行为等价 |
| **CR-024** `set_resampler` | `quality: HQ\|VHQ\|24BIT`、`phase: linear\|minimum\|intermediate\|maximum`、`steep`；成功 emitState；播放中重建（≤100ms，如实 applied） | **默认 VHQ/linear/非 steep 与现状一致**（selftest 断言） |
| **CR-025** `set_dither` | 六档：off/tpdf/highpass-tpdf/ns-5/ns-9/ultra-shaped（SoX 系数，注明来源）；`state.dither {mode,active}` | **默认 tpdf 与原算法逐样本一致**；float/bit-perfect 永不 dither |
| **CR-026** `set_channels` 扩展 | `monoMode`、低/中/高三频段 L/R 增益（LR2 200Hz/2kHz）、每声道延迟 0–10ms；`state.dsp.channels` 扩展 + `dspModules` | **全 0 完全旁路（逐位恒等，selftest）** |
| **CR-027** `set_output.latencyProfile` | stable（buffer≈8192 帧）/ balanced（现状）/ lowLatency（请求最小周期，拿不到就如实报实际） | **balanced = 上一轮逐点一致** |
| IR 口径 | 无 IR 时 `set_ir{enabled:true}` 拒绝（ok:false，state 不变）；preamp 越界拒绝不 clamp；IR 生效时 bit-perfect=false | 恢复段补齐 selftest |

### 1.2 应用主进程（`app/src/main`、`preload`）
- **播放记忆**：`main/playback-memory.ts` + `shared/playback-memory.ts`；只存「绝对路径 + trackId + 位置/时长 + 队列 id + 循环模式 + 时间戳」，2s debounce / 位置 5s 节流 / will-quit 同步补写；**绝不自动 open/play**；文件不存在时不恢复（记录保留）。
- **下一首预热**：`main/prefetch.ts`；校验绝对路径/音频扩展名/文件存在；1MB 块 + setImmediate 让出事件循环 + 8MB 封顶 + 可取消；返回 `{ok,bytes,ms,error?,cancelled?}`。
- **-460 风控熔断**：manager 统一请求层识别 body code -460/460、裸 403/418、400 包裹的 Cheating → `block()` 10 分钟，所有入口不再打上游；单测 3 条。
- **IPC 四向对账**：新增 `tools/ipc-surface.test.mjs`（handler ↔ preload ↔ d.ts ↔ renderer 调用），补齐 `eq-models-count` 漏暴露。

### 1.3 渲染层（`app/src/renderer`）
- **设置页四组专业控件**（重采样/dither/延迟档位/声道工具）：localStorage 持久化，握手后与输出偏好一起重下发；ERR_UNSUPPORTED 显示「引擎不支持」并回滚；**请求 vs 实际**分开展示。
- **EQ A/B + 撤销升级**：快照含 EQ + 声道工具（CR-026 字段）；MAX_UNDO=20；切换/撤销同时发 `set_eq` + `set_channels`。
- **播放恢复入口**：启动读记忆 → 解析 catalog（trackId 优先、路径兜底）→「继续上次：曲名 · m:ss」横幅；点击 open+seek 且**保持暂停**；忽略即 clear。
- **ReplayGain**：默认关；开启后当前曲目首次 playing 发 `analyze_loudness {async:true}`（同曲只发一次）→ `loudness_done` 配对 replyId → `set_replaygain {mode:'track', trackGainDb, trackPeak: peakLinear, preventClip:true}`；关闭即 `mode:'off'`；防削波用**真峰值**。
- **深度播放等价优化**：SpectrumGlow 定时器/属性写入收敛（同路径不写 DOM）、LyricsView 逐字填充缓存、沉浸视图不挂载隐藏 rail；**不降视觉频率**。

### 1.4 明确不移植（诚实边界）
DSD/SDM、ASIO/miniaudio/libav/CUDA、AirPlay/HQPlayer、真 gapless（与 stream reuse 同一底座）、MV/桌面歌词/任务栏/主题工坊/插件/云盘——理由见 ECHO-NEXT-PORT-SPEC §4。

### 4.3 深度播放状态（immersive：歌词+频谱光带+唱片+meter+EQ 开）

**诚实边界**：本轮中途用户插入了 USB DAC，默认端点由内置扬声器变为 DAC（shared→exclusive 6ms），因此 before/after **无法在同端点同模式上做绝对对照**；以下用同构建内的归因与 profile 结论：

- 渲染层 CDP profile（immersive 11.1s）：JS 自耗时合计 ~120ms（≈1.1% 单核），无单点 >0.2%；`setAttribute`/`smoothPathFromArrays`/`spectrumCurvePath`/`gl clear`/rAF 各十几到二十几 ms。**等价优化已把 JS 压到 <1%**，主成本是原生栅格/合成（GPU 2.2–3.0%）——继续降只能改视觉频率/面积（R1，未做，见 §8）。
- 可测量的深播相关收益来自**非渲染路径**：①播放中切到曲库/设置等无 meter 消费者页面，引擎 5%→1.95–2.73%（A5+E2）；②隐藏窗口引擎 5.08–5.47%→0.78–1.56%；③播放记忆/RG/预热默认不增加常驻成本（RG 默认关；预热 8MB 13ms）。
- 沉浸场景保持 meter（设计如此）：引擎稳态 ~4.7–5.2%（其中 meter 分析约 2.4%）。下一步的明确候选是 meter FFT 补零 4×→2×（需独立 A/B）与频谱绘制 45fps 上限（需 owner 视觉裁定）。

**独立验证者（Window C，speaker-pinned，engine/Tab/GPU）**：home+EQ **6.41**/1.57/2.30（before 7.19/1.21/1.62）；immersive **4.62**/1.15/2.01（before 4.68/1.36/2.03）；音效页 **0.72**/0.59/1.18（before 2.65/0.44/0.89）；回 home **3.57**/1.69/2.47（before 3.95/1.39/2.07）；meter 70fps/352B；immersive rAF 90.2。
→ 结论：引擎深播 CPU 在 meter 开启场景**持平**（4.62 vs 4.68，已到 meter 分析成本下限）、在无 meter 消费者页面/隐藏场景大幅下降（2.65→0.72 等）；渲染层 Tab/GPU 在 ±0.2–0.5 的噪声内（等价优化不改变 paint，符合预期）。**不宣称渲染层深播百分比收益**，只宣称 JS 热点已消除与引擎侧真实下降。
- 口径坑：`--device=default` 不是有效设备 id（引擎当前回 ok 但不开流；应回 ERR_DEVICE——已记入下轮）；默认端点 no-pin 组的 immersive 7.47% 与 speaker-pinned 4.62% 不一致，按端点/模式差异与运行间差异处理，不作结论。

## 8. 未做 / 风险 / 已知 flake（诚实清单）

1. **stream reuse / 真 gapless**：切歌仍有 34ms 级 stop/start（渲染线程 teardown + AVRT + 5ms 排空），与 gapless 同一块底座。
2. **meter FFT 补零 4×→2×**：深播引擎最大单项仍是 meter 分析 (~2.4% 单核)；实验需改 meter.hpp 常量并重链（会让冻结 sha 变化），按独立 A/B 排期。
3. **频谱/光带 45fps 上限**：估算 Tab -0.3~0.4%、GPU -0.4~0.5%，但会改观感——**待 owner 决定**，本轮不做。
4. **SMTC（CR-014 已接受但双端零实现）**、30min 独占 0 xrun 硬指标（需 owner 同意出声跑一次并归档）、DSD/SDM、ASIO、MV、桌面歌词、迷你模式、全局快捷键。
5. **元数据补全（Picard/AcoustID）**、catalog/trackId 持久化（CONTRACT §3.5 文本 vs 内存 catalog）、下载器/OPTIMIZE 文档一致性更正（审计 K 区 15 条）。
6. **E5 启动并行化**（spawn→ready 中位 136.6ms；需改 ready 语义，协议/行为裁定）。
7. **已知测试 flake（非产品回归）**：`test:startup` 偶发 1/3（`.startup-scene` 竞态；产品无 pageerror、intro 正常 ~2.5s 退出）；`tools/engine-host.test.mjs` 时序断言（已放宽等待）。建议下轮给 startup harness 加 retry/稳定性等待，而不是继续放宽超时。
8. **口径坑（已记录）**：`--device=default` 不是有效设备 id（引擎当前回 ok 但不开流，应回 ERR_DEVICE——下轮修）；深播 before/after 因默认端点从内置扬声器切到 USB DAC，不可跨端点直接对比；切歌 open 有两个冷文件首触 ~1s 离群（before 同口径也有，机制未完全定位，建议下轮用 Process Monitor 确认是否杀软/首次读）。
